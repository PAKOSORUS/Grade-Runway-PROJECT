## สมมติฐานสำคัญที่ใช้ (ต้องการยืนยันจากผู้ใช้)

1. ตัวเลขเกณฑ์ทุกค่าดึงจากการตั้งค่า ไม่ hardcode ในหน้าจอ ตัวเลขใน mock เป็น "ตัวอย่าง" เท่านั้น ไม่ใช่ค่าตั้งต้นจริง
2. ไม่มี user journey ของผู้ดูแลระบบ จึงออกแบบหน้า `admin-threshold-settings` เป็นฟอร์มแก้เกณฑ์แบบเรียบง่ายจาก US4/BR2
3. ระบบมีข้อมูลเกรด/การเข้าเรียน/การส่งงานอยู่แล้ว นักศึกษาไม่ต้องกรอก (ยังไม่ระบุว่ามี sync จากระบบภายนอก)
4. แจ้งเตือนหนึ่งรายการต่อหนึ่งตัวแปรที่เข้าเงื่อนไข ถ้าเข้าหลายตัวแปรพร้อมกันจะรวมเป็นรายการระดับ danger ด้านบนสุดและแตกรายละเอียดในหน้า alert-detail
5. ผู้ใช้ใหม่ที่ข้อมูลย้อนหลังไม่พอ จะเห็นข้อความบอกสาเหตุและคำแนะนำทั่วไปที่ติดป้ายว่าเป็นคำแนะนำทั่วไป
6. เมื่อแอดมินแก้เกณฑ์ แจ้งเตือนที่ค้างอยู่ยังคงอยู่และระบุว่าอิงเกณฑ์ ณ เวลาที่แจ้ง
7. ไม่ออกแบบ feedback loop ว่านักศึกษานำคำแนะนำไปใช้จริงหรือไม่ (spec ไม่ระบุ)
8. ไม่ทำหน้าจอสำหรับช่องทางแจ้งเตือนอื่น (อีเมล/LINE/SMS), การใช้งานในบริบทองค์กร, และการเชื่อมระบบเกรดภายนอก (Won't have)

**เปิดต้นแบบเชิงโต้ตอบ:** [interactive-prototype.html](./interactive-prototype.html) — เปิดไฟล์นี้ในเบราว์เซอร์เพื่อคลิกทดลองใช้งานจริงได้ทันที (ไม่ต้องต่อเน็ต ยกเว้นฟอนต์) ข้อมูลเป็น mock ฝั่ง client รีเซ็ตเมื่อรีเฟรชหน้า
