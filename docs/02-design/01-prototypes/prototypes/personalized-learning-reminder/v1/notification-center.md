## จุดประสงค์ของหน้าจอ

รองรับ Feature #3 (แจ้งเตือน in-app ทันที) และ BR4 โดยแสดงรายการแจ้งเตือนย้อนหลังทั้งหมด และกำหนดรูปแบบ toast ที่เด้งขึ้นทันทีเมื่อระบบตรวจพบว่าเข้าเงื่อนไขความเสี่ยง

## องค์ประกอบ (Components)

| โซน | คอมโพเนนต์ (อ้างอิง DESIGN.md) | เนื้อหา/พฤติกรรม |
|---|---|---|
| Header | Navigation (3.7) | ปุ่ม Ghost "ทำเครื่องหมายว่าอ่านทั้งหมด" |
| Toast | In-app toast (3.4) | มุมบนขวา สี semantic ตามระดับ หายใน 6 วินาที ยกเว้นระดับ danger ต้องกดปิดเอง พื้นหลังโทนอ่อน ใช้ `--color-danger-500` เฉพาะขอบ/ไอคอน/ข้อความ (ห้ามพื้นเต็ม) |
| รายการแจ้งเตือน | Notification center / list (3.4) | เรียงใหม่ไปเก่า แต่ละแถวมีไอคอนสถานะ + timestamp (`--font-size-caption`, `--color-neutral-500`) แถวที่ยังไม่อ่านมีจุดและตัวหนา แถวที่กดได้มี focus state |
| ป้ายระดับ | Badge (3.3) | ต้องเฝ้าระวัง (warning) / ความเสี่ยงสูง (danger) พร้อมข้อความและไอคอน |
| แถวกลุ่มเสี่ยงหลายตัวแปร | Card (3.2) + แถบ danger ซ้าย 4px | หนึ่งแถวสรุป "เข้าเงื่อนไขหลายตัวแปรพร้อมกัน" ปักบนสุด ตามสมมติฐานของ overview |

## States

- **Default:** รายการแจ้งเตือนผสมอ่านแล้ว/ยังไม่อ่าน
- **Empty state (4.5):** "ยังไม่มีการแจ้งเตือน — ผลการเรียนของคุณอยู่ในเกณฑ์ปกติ ระบบจะแจ้งเมื่อพบว่ามีตัวแปรเข้าเงื่อนไขเฝ้าระวัง" พร้อมลิงก์ไป learning-status-overview
- **Loading:** skeleton แถวรายการ
- **Error:** "โหลดการแจ้งเตือนไม่สำเร็จ ตรวจสอบการเชื่อมต่อแล้วลองใหม่" พร้อมปุ่ม "ลองใหม่"

## Interaction & Edge Cases

- กดแถวแจ้งเตือน เปิด alert-detail และแถวเปลี่ยนเป็นสถานะอ่านแล้ว
- เข้าเงื่อนไขหลายตัวแปรพร้อมกัน — จัดกลุ่มเป็นรายการ danger หนึ่งรายการ (ลำดับความสำคัญ/การจัดกลุ่มไม่ได้ระบุใน spec ใช้สมมติฐาน) _(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_
- แอดมินแก้เกณฑ์ขณะมีแจ้งเตือนค้าง — แจ้งเตือนเดิมคงอยู่และมีหมายเหตุ "อิงเกณฑ์ ณ เวลาที่แจ้ง" _(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_
- ช่องทางอื่นนอกเหนือ in-app (อีเมล, LINE, SMS) ไม่อยู่ในขอบเขต ไม่มี UI ตั้งค่าช่องทาง
