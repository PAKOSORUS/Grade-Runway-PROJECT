## จุดประสงค์ของหน้าจอ

ให้ผู้ดูแลระบบปรับเกณฑ์ของตัวแปรที่ใช้แจ้งเตือนได้ (Feature #6, BR2: configurable ห้าม hardcode) และแสดงหมวดหมู่ผู้ใช้งานที่ระบบรองรับเพื่อสะท้อนสถาปัตยกรรมที่ขยายได้ (Feature #7, Could have)

## องค์ประกอบ (Components)

| โซน | คอมโพเนนต์ (อ้างอิง DESIGN.md) | เนื้อหา/พฤติกรรม |
|---|---|---|
| Top nav | Navigation (3.7) | Active ขีดเส้นใต้ `--color-accent-gold-500` |
| ป้ายหมวดหมู่ผู้ใช้งาน | Badge (3.3) | แสดง "นักเรียน/นักศึกษา" แบบอ่านอย่างเดียว หมวดอื่นยังไม่เปิดใช้ (ตามขอบเขต) |
| การ์ดต่อตัวแปร | Card (3.2) | ชื่อตัวแปร (h2) + สวิตช์เปิด/ปิด + ช่องกรอกค่าเกณฑ์ + helper text (caption) ว่าค่านี้มีผลกับการแจ้งเตือนครั้งถัดไป |
| ฟอร์ม | ฟอร์ม/Input (3.6) | Label อยู่เหนือ input ขอบ `--color-neutral-300` เมื่อ focus ขอบ `--color-primary-600` หนา 2px |
| ข้อความ error | ฟอร์ม (3.6) | `--color-danger-500` + `--font-size-caption` เช่น "ค่าเกณฑ์ต้องเป็นตัวเลขและไม่เว้นว่าง" |
| ปุ่มบันทึก/ยกเลิก | Button Primary / Secondary (3.1) | บันทึกแล้วแสดงข้อความยืนยันแบบ toast (success) |

## States

- **Default:** แสดงค่าเกณฑ์ปัจจุบัน
- **Empty state (4.5):** ยังไม่ตั้งค่าเกณฑ์ใดเลย — "ยังไม่มีการกำหนดเกณฑ์ ระบบจะยังไม่แจ้งเตือนจนกว่าจะกำหนดอย่างน้อยหนึ่งตัวแปรและกดบันทึก" _(ค่าตั้งต้น: ต้องการข้อมูลเพิ่มเติมจากผู้ใช้ ตาม spec ให้กำหนดที่ 02-technical)_
- **Validation error:** ช่องที่ผิดแสดงข้อความ error ใต้ input และไอคอนกำกับ (ไม่ใช้สีอย่างเดียว)
- **Saving/Error:** ปุ่มบันทึกแสดง loading / "บันทึกไม่สำเร็จ ตรวจสอบการเชื่อมต่อแล้วลองใหม่"

## Interaction & Edge Cases

- ผู้ดูแลแก้เกณฑ์ขณะมีแจ้งเตือนที่ยังไม่อ่านค้าง — แสดงข้อความเตือนก่อนบันทึก "แจ้งเตือนที่ส่งไปแล้วจะไม่ถูกประเมินย้อนหลัง" _(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_
- ปิดตัวแปรทั้งหมด — แสดงคำเตือนว่าระบบจะไม่ส่งแจ้งเตือน
- ไม่มีช่องทางแจ้งเตือนอื่นให้ตั้งค่า (อีเมล/LINE/SMS เป็น Won't have)
- ไม่มี UI สลับบริบทองค์กร (Won't have) มีเพียงป้ายหมวดหมู่ read-only
