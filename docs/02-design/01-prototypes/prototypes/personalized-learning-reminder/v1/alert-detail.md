## จุดประสงค์ของหน้าจอ

ให้นักศึกษาเข้าใจว่า "ทำไมจึงได้รับการแจ้งเตือนนี้" โดยบอกตัวแปรที่เข้าเงื่อนไข ค่าของตนเอง และเกณฑ์ปัจจุบัน พร้อมลิงก์ไปคำแนะนำ ตอบ Feature #2/#3 และอุดช่องว่างของ journey ขั้น "เปิดดูรายละเอียดการแจ้งเตือน" (คะแนน 2 สมมติฐานว่ามีลิงก์ไปหน้าคำแนะนำโดยตรง)

## องค์ประกอบ (Components)

| โซน | คอมโพเนนต์ (อ้างอิง DESIGN.md) | เนื้อหา/พฤติกรรม |
|---|---|---|
| Header | Navigation (3.7) | ปุ่มย้อนกลับไป notification-center |
| สรุปการแจ้งเตือน | Card (3.2) + Badge (3.3) | แถบซ้าย 4px สี `--color-warning-500` หรือ `--color-danger-500` ตามระดับ ข้อความโทนสนับสนุน เช่น "ผลการเรียนช่วงนี้มีแนวโน้มลดลง ลองดูคำแนะนำนี้นะ" (4.2) |
| ตารางตัวแปร | ตาราง + tabular-nums (2.2) | แสดงค่าของนักศึกษาเทียบเกณฑ์ที่ดึงจากการตั้งค่า (ไม่ hardcode ตาม 4.1) |
| ปุ่มไปคำแนะนำ | Button Primary (3.1) | ไป personalized-advice (ตัวแปรที่เกี่ยวข้องถูกไฮไลต์) |
| ปุ่มรับทราบ | Button Ghost (3.1) | ทำเครื่องหมายอ่านแล้ว กลับไป notification-center |

## States

- **Default:** แสดงรายละเอียดตามแจ้งเตือนที่เลือก (กรณีหลายตัวแปรจะมีหลายแถวในตาราง)
- **Empty state (4.5):** ถ้าเปิดแจ้งเตือนที่ไม่มีอยู่แล้ว (เช่น ถูกล้าง) — "ไม่พบการแจ้งเตือนนี้ อาจถูกลบหรือหมดอายุ" พร้อมปุ่มกลับไปศูนย์การแจ้งเตือน
- **Loading/Error:** skeleton ของการ์ด / "โหลดรายละเอียดไม่สำเร็จ ลองใหม่อีกครั้ง"

## Interaction & Edge Cases

- ห้ามแสดงป้ายเสี่ยงลอยๆ โดยไม่มีทางออก — ต้องมีปุ่มไปคำแนะนำอยู่ในหน้าเสมอ (4.1)
- เข้าเงื่อนไขหลายตัวแปร — แสดงทุกตัวแปรในตารางเดียว เรียงตามระดับความเสี่ยง _(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_
- แอดมินเปลี่ยนเกณฑ์หลังแจ้งเตือนออกไปแล้ว — ใช้เกณฑ์ ณ เวลาที่แจ้งในตาราง และแสดงหมายเหตุ _(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_
