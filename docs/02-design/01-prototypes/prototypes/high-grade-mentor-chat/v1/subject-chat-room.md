## จุดประสงค์ของหน้าจอ

หน้าสนทนาหลักของห้องแชทแต่ละวิชา ให้ผู้แนะนำที่ผ่านการอนุมัติโพสต์คำแนะนำ/รีวิววิธีเรียน (US1) และนักศึกษาทั่วไปอ่านข้อความที่เผยแพร่แล้วพร้อมตั้งคำถามขอคำแนะนำ (US2) โดยทุกข้อความไม่ว่าใครส่งต้องผ่าน pre-moderation ก่อนคนอื่นเห็น (BR4) และผู้ส่งต้องเห็นสถานะข้อความของตัวเองชัดเจนทุกขั้น (DESIGN 4.1 — ความโปร่งใสของสถานะ moderation)

## องค์ประกอบ (Components)

| โซน | คอมโพเนนต์ (อ้างอิง DESIGN.md) | เนื้อหา/พฤติกรรม |
|---|---|---|
| Header | Navigation (3.7) | ปุ่มย้อนกลับ + ชื่อวิชา |
| ข้อความในห้องแชท | Chat/Message Bubble (3.5) | ข้อความตนเอง: ชิดขวา พื้น `--color-primary-100`; ข้อความผู้อื่น: ชิดซ้าย พื้น `--color-neutral-100`; radius `--radius-lg` (มุมฝั่งผู้ส่งใช้ `--radius-sm`) |
| ป้ายกำกับผู้แนะนำ | Badge (3.3) มงกุฎ/ดาวทอง | พื้น `--color-accent-gold-100`, ข้อความ `--color-accent-gold-700` ติดข้างชื่อผู้ส่งที่เป็น mentor ที่อนุมัติแล้ว |
| สถานะรอตรวจ (เห็นเฉพาะผู้ส่ง) | Badge (3.3) "รอตรวจ" | พื้น `--color-warning-500` โทนอ่อน 10% + ข้อความ `--color-warning-500` พร้อม label "รอการตรวจสอบ — ยังไม่เผยแพร่" ตามกฎ 3.5 |
| สถานะถูกปฏิเสธ (เห็นเฉพาะผู้ส่ง) | Badge (3.3) | พื้น `--color-danger-500` โทนอ่อน 10% + ข้อความ `--color-danger-500` พร้อมเหตุผลสั้นๆ ใต้ข้อความ ตาม Tone of Voice (4.2) |
| ช่องพิมพ์ข้อความ | Input/Textarea (3.6) | ขอบ `--color-neutral-300`, focus เปลี่ยนเป็น `--color-primary-600` หนา 2px, ไม่มี label ลอยเพราะเป็น composer ไม่ใช่ฟอร์มมาตรฐาน (ใช้ placeholder "พิมพ์ข้อความ...") |
| ปุ่มส่ง | Button Primary (3.1) | พื้น `--color-primary-600`, ข้อความขาว, ขนาดพื้นที่กด ≥ 44×44px (4.4) |
| Panel รายชื่อผู้แนะนำ (desktop) | Card (3.2) + Badge (3.3) | รายชื่อ mentor ที่อนุมัติแล้วในวิชานี้ |

## States

- **Default:** แสดงข้อความที่เผยแพร่แล้วทั้งหมด (เรียงเก่า→ใหม่) บวกข้อความของตนเองที่ยังรอตรวจ/ถูกปฏิเสธ (เห็นเฉพาะตนเอง)
- **Empty state (4.5):** วิชาที่ยังไม่มีผู้แนะนำหรือยังไม่มีข้อความเลย — ข้อความอธิบาย เช่น "ยังไม่มีผู้แนะนำในวิชานี้ คุณสามารถตั้งคำถามไว้ก่อนได้ เมื่อมีผู้แนะนำจะเห็นคำถามของคุณ" (สอดคล้องกับ Tone of Voice 4.2 — ให้กำลังใจ ไม่ปล่อยว่างเปล่า)
- **Loading:** skeleton bubble ระหว่างโหลดประวัติข้อความ
- **Error:** ส่งข้อความไม่สำเร็จ — แสดงไอคอน error ข้าง bubble พร้อมปุ่ม "ลองส่งอีกครั้ง" ระบุสาเหตุที่เป็นไปได้ (เช่น "เครือข่ายมีปัญหา")

## Interaction & Edge Cases

- ทุกข้อความ (ทั้งจากผู้แนะนำและนักศึกษาทั่วไป) ต้องผ่านคิว pre-moderation ก่อนเผยแพร่เสมอตาม BR4 — แสดง badge "รอตรวจ" ทันทีหลังกดส่ง
- ข้อความที่ถูกแอดมินปฏิเสธ — แสดงเหตุผลสั้นๆ กำกับเสมอ (Tone of Voice 4.2) และผู้ใช้พิมพ์ส่งใหม่ได้ _(สมมติฐาน — สเปกไม่ได้ยืนยันตรงๆ ว่ามีการแจ้งเหตุผลหรือส่งซ้ำได้)_
- การเข้าถึงจำกัดเฉพาะนักศึกษาที่ลงทะเบียนวิชานั้นในภาคปัจจุบัน (BR3) — หากพยายามเข้าห้องแชทวิชาที่ไม่ได้ลงทะเบียน ต้อง block และแสดงข้อความอธิบายสาเหตุ (ไม่ใช่หน้าเปล่า/error ทั่วไป)
- ระยะเวลารอตรวจสอบ (SLA) ไม่ระบุใน spec — ใช้ถ้อยคำกลางๆ "อยู่ระหว่างตรวจสอบ" แทนตัวเลขเวลาที่แน่นอน _(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_
