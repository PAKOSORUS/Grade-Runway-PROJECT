## จุดประสงค์ของหน้าจอ

หน้าทางเข้าหลักที่ใช้ร่วมกันทั้งนักศึกษาเกรดสูง/ผู้แนะนำ และนักศึกษาทั่วไป แสดงเฉพาะห้องแชทของวิชาที่ผู้ใช้ลงทะเบียนเรียนอยู่ในภาคการศึกษาปัจจุบันเท่านั้น (BR2 — แยกห้องตามรายวิชา, BR3 — จำกัดสิทธิ์ตามการลงทะเบียนภาคปัจจุบัน) เป็นก้าวแรกก่อนเข้าสู่การอ่าน/โพสต์คำแนะนำใน `subject-chat-room`

## องค์ประกอบ (Components)

| โซน | คอมโพเนนต์ (อ้างอิง DESIGN.md) | เนื้อหา/พฤติกรรม |
|---|---|---|
| Header/Nav | Navigation (3.7) — top nav บน desktop, bottom tab bar บนมือถือตามกฎ Responsive (4.3) | ชื่อหน้า "ห้องแชทรายวิชา" |
| การ์ดห้องแชทต่อวิชา | Card (3.2) | ชื่อวิชา (`--font-size-h2`), ตัวอย่างข้อความล่าสุด (`--font-size-body`), timestamp (`--font-size-caption`, สี `--color-neutral-500`) |
| สถานะผู้แนะนำในวิชา | Badge (3.3) รูปแบบ "ผู้แนะนำเกรดสูง" | มีผู้แนะนำ: พื้น `--color-accent-gold-100` + ข้อความ `--color-accent-gold-700` + ไอคอนมงกุฎ/ดาวทอง; ไม่มีผู้แนะนำ: พื้น `--color-neutral-100` + ข้อความ `--color-neutral-700` "ยังไม่มีผู้แนะนำ" |
| จำนวนข้อความยังไม่อ่าน | Badge (3.3) แบบ pill ตัวเลข | พื้น `--color-primary-600`, ตัวอักษรขาว, รูปร่าง `--radius-full` |

## States

- **Default:** แสดงเฉพาะวิชาที่ผู้ใช้ลงทะเบียนภาคปัจจุบัน เรียงจากข้อความล่าสุดไปเก่า
- **Empty state (4.5):** ถ้ายังไม่มีวิชาที่ลงทะเบียนในภาคนี้ หรือระบบยังไม่ผูกข้อมูลการลงทะเบียน — แสดงข้อความอธิบายสาเหตุ เช่น "คุณยังไม่มีห้องแชทในภาคการศึกษานี้ เพราะยังไม่พบข้อมูลการลงทะเบียนวิชา" พร้อมปุ่ม Ghost/Text (3.1) "ตรวจสอบการลงทะเบียน"
- **Loading:** skeleton card 3-4 แถวแทนที่รายการจริงระหว่างโหลด
- **Error (4.5):** ระบุสาเหตุ+วิธีแก้ที่ทำได้จริง เช่น "โหลดรายการห้องแชทไม่สำเร็จ กรุณาลองใหม่อีกครั้ง" พร้อมปุ่ม Secondary (3.1) "ลองอีกครั้ง"

## Interaction & Edge Cases

- วิชาที่ยังไม่มีนักศึกษาผ่านเกณฑ์เป็นผู้แนะนำเลย — ยังเข้าห้องแชทได้ปกติ แต่แสดง badge "ยังไม่มีผู้แนะนำ" เพื่อตั้งความคาดหวังล่วงหน้า (Edge Case จาก User Journey นักศึกษาทั่วไป)
- นักศึกษาลงทะเบียนวิชาใหม่ระหว่างภาค (เพิ่ม/ถอนวิชา) _(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้ — สมมติฐานที่ใช้: รายการห้องแชทอัปเดตทันทีที่ระบบลงทะเบียนยืนยันการเพิ่ม/ถอนวิชาสำเร็จ ไม่มีดีเลย์เพิ่มเติมในระดับ UI)_
