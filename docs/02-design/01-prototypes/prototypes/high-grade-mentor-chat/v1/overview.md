## สมมติฐานสำคัญที่ใช้ (ต้องการยืนยันจากผู้ใช้)

1. เกณฑ์เกรด/GPA เป็นค่าที่แอดมินตั้งเองต่อวิชา ไม่มีค่าเริ่มต้น hardcode ในหน้าจอ
2. คิวอนุมัติผู้แนะนำและคิว pre-moderation เป็นคิวกลางเดียว ยังไม่แยกตามอาจารย์ประจำวิชา
3. ไม่แสดง SLA/เวลารอที่แน่นอนในหน้าจอ ใช้ถ้อยคำกลางๆ แทน และยังไม่มี UI กระจายงานให้แอดมินหลายคน
4. การแจ้งผลอนุมัติ/ปฏิเสธสิทธิ์ผู้แนะนำใช้รูปแบบ Notification center (DESIGN 3.4)
5. ข้อความ/คำขอที่ถูกปฏิเสธจะแสดงเหตุผลเสมอ และผู้ใช้ส่งใหม่ได้ไม่จำกัดจำนวนครั้ง
6. ห้องแชทของวิชาที่เพิ่ม/ถอนกลางภาคจะปรากฏใน `chat-room-list` ทันทีที่ระบบลงทะเบียนยืนยันสำเร็จ
7. ยังไม่ออกแบบกลไก/หน้าจอถอนสิทธิ์ผู้แนะนำเมื่อเกรดภาคถัดไปตกต่ำกว่าเกณฑ์ (รอ requirement เพิ่มเติม)

**เปิดต้นแบบเชิงโต้ตอบ:** [interactive-prototype.html](./interactive-prototype.html) — เปิดไฟล์นี้ในเบราว์เซอร์เพื่อคลิกทดลองใช้งานได้ จำลองทั้ง 3 มุมมอง (นักศึกษาทั่วไป / นักศึกษาเกรดสูง-ผู้แนะนำ / ผู้ดูแลระบบ) ครอบคลุมทั้ง 6 หน้าจอข้างต้น โดยแหล่งข้อมูลแบ่งเป็น 2 ส่วน

- **หน้าจอ 1 (รายการห้องแชทตามวิชา) อ่านจาก Firestore จริง** — ใช้ `terms` ที่ `is_current = true`, `enrollments` ของผู้ใช้ตัวอย่าง และ `chatRooms` (มุมมองนักศึกษาทั่วไปใช้ `user-s02`, มุมมองผู้แนะนำใช้ `user-s01`) มีสถานะ loading / error / empty ตาม wireframe
  - ต้องต่ออินเทอร์เน็ต (โหลด Firebase SDK และฟอนต์จาก CDN)
  - ต้องมีไฟล์ `firebase-config.web.js` ในโฟลเดอร์เดียวกับ HTML (คัดลอกจาก `firebase-config.web.example.js` แล้วใส่ค่าจาก Firebase Console ไฟล์นี้ถูกกันไว้ใน `.gitignore`) ถ้าไม่มี จะแสดงข้อความ error พร้อมปุ่ม "ลองอีกครั้ง"
  - ต้องมีข้อมูลใน Firestore ก่อน โดยรัน `node scripts/seed-firestore.js` (ดู `scripts/README.md`)
- **หน้าจอ 2–6 ยังเป็น mock ฝั่ง client เท่านั้น** (ห้องแชท, สถานะผู้แนะนำ, คิวอนุมัติ, คิวตรวจข้อความ, ตั้งค่าเกณฑ์) รีเซ็ตเมื่อรีเฟรชหน้า การคลิกการ์ดห้องแชทจากหน้าจอ 1 จะแสดงข้อความแจ้งว่าหน้าห้องแชทยังเป็นข้อมูลจำลอง และยังไม่เปิดห้องจริง

หมายเหตุ: ข้อความบรรยาย (caption) ใต้แท็บมุมมองและหัวข้อในหน้าเว็บยังอ้างข้อมูลจำลองชุดเดิม (CS101, MATH204, ENG150) ซึ่งไม่ตรงกับวิชาใน Firestore (SE101, SE201, SE202)
