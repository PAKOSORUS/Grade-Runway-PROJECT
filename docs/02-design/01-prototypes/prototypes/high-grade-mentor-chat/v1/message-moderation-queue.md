## จุดประสงค์ของหน้าจอ

ให้ผู้ดูแลระบบตรวจสอบทุกข้อความในทุกห้องแชท (ทั้งจากผู้แนะนำและนักศึกษาทั่วไป) ก่อนเผยแพร่ให้คนอื่นเห็น (BR4, US5) เพื่อรับประกันว่าเนื้อหาที่ปรากฏเหมาะสมและเป็นประโยชน์

## องค์ประกอบ (Components)

| โซน | คอมโพเนนต์ (อ้างอิง DESIGN.md) | เนื้อหา/พฤติกรรม |
|---|---|---|
| Header/Nav | Navigation (3.7) | เมนูแอดมิน |
| ตัวกรอง | Form/Select (3.6) | เลือกวิชา |
| การ์ดข้อความรอตรวจ | Card (3.2) + Chat bubble content (3.5 เนื้อหาข้อความ) | แสดงตัวตนผู้ส่ง (พร้อม badge ทองถ้าเป็น mentor), เนื้อหาข้อความเต็ม, วิชา, เวลา |
| สถานะ | Badge (3.3) "รอตรวจ" | พื้น/ข้อความ `--color-warning-500` โทนอ่อน |
| ปุ่ม action | Button Primary "อนุมัติ" (3.1) / Button Danger "ปฏิเสธ" (3.1) | กด "ปฏิเสธ" ต้องกรอกเหตุผลสั้นๆ ใน Textarea (3.6) ตาม Tone of Voice (4.2) — ห้ามใช้ข้อความสำเร็จรูปที่ไม่สื่อความ |

## States

- **Default:** แสดงข้อความที่รอตรวจทั้งหมด เรียงเก่า→ใหม่ (FIFO) เพื่อไม่ให้ข้อความค้างนาน
- **Empty state (4.5):** ไม่มีข้อความรอตรวจ — ข้อความให้กำลังใจ เช่น "ไม่มีข้อความรอตรวจสอบในขณะนี้ ดีมากครับ/ค่ะ"
- **Loading:** skeleton การ์ด
- **Error:** อนุมัติ/ปฏิเสธไม่สำเร็จ — แจ้งสาเหตุ+ปุ่มลองใหม่ (4.5)

## Interaction & Edge Cases

- ทุกข้อความไม่ว่าจากผู้แนะนำหรือนักศึกษาทั่วไปต้องเข้าคิวนี้เหมือนกันทั้งหมด (ตีความจาก BR4 "ทุกข้อความ") — คำถามของนักศึกษาทั่วไปเมื่อถูกปฏิเสธ ผู้ถามจะทราบเหตุผลผ่านสถานะใน `subject-chat-room` เสมอ
- ปริมาณข้อความมากเกินกำลังของแอดมินคนเดียว หรือหลายวิชาพร้อมกัน — ยังไม่มีกลไกกระจายงาน/SLA ระบุใน spec เวอร์ชันนี้ใช้ filter ตามวิชาเป็นตัวช่วยลดปริมาณเบื้องต้นเท่านั้น `_(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_`
- ผู้รับผิดชอบ pre-moderation เป็นแอดมินส่วนกลางหรืออาจารย์ประจำวิชา ยังไม่ชี้ชัดในสเปก — เวอร์ชันนี้ออกแบบเป็นคิวกลางเดียวที่ผู้มีบทบาท "ผู้ดูแลระบบ/ผู้ได้รับมอบหมาย" ทุกคนเข้าถึงร่วมกัน `_(ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_`
