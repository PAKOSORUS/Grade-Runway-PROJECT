# DESIGN.md — Design System: Grade Runway

**วันที่สร้าง:** 2026-08-27
**สถานะ:** Draft v1

เอกสารนี้เป็น **design system กลาง** ของ Grade Runway ใช้เป็นแหล่งอ้างอิงร่วมสำหรับทุกฟีเจอร์ในโปรเจกต์ ต่างจากเอกสารใน [[01-prototypes/index|01-prototypes]] ที่ผูกกับ requirement รายฟีเจอร์ (มีวันที่/เลขนำหน้า) เอกสารนี้เป็นเอกสารมีชีวิต (living document) ที่ปรับปรุงต่อเนื่องเมื่อมีคอมโพเนนต์หรือกฎ UX ใหม่เพิ่มเข้ามา

โทนสีอ้างอิงจากอัตลักษณ์ของ **มหาวิทยาลัยแม่ฟ้าหลวง (Mae Fah Luang University)** ตามโลโก้ที่ผู้ใช้แนบให้ (พื้นแดง สัญลักษณ์เจดีย์/เปลวไฟสีทอง-แดงเลือดหมู)

**ใช้อ้างอิงร่วมกับ:**
- [[01-prototypes/index|01-prototypes]] — นำ token/คอมโพเนนต์ในนี้ไปใช้ทำ wireframe/mockup รายฟีเจอร์
- [[02-technical/index|02-technical]] — นำ token ไปใช้กำหนด implementation จริง (เช่น CSS variables, theme config)

## 1. Brand Identity & CI

### 1.1 แนวคิดหลัก

Grade Runway อ้างอิงอัตลักษณ์จากมหาวิทยาลัยแม่ฟ้าหลวง เพื่อสื่อถึงความเป็นสถาบันการศึกษา ความน่าเชื่อถือ และความใส่ใจต่อผู้เรียน โทนสีหลักคือ **แดงเลือดหมู (Maroon Red)** คู่กับ **ทอง (Gold)** ซึ่งเป็นสีที่ปรากฏในโลโก้มหาวิทยาลัย (เจดีย์ทองบนพื้นแดง มีสัญลักษณ์เปลวไฟสีแดง-ทองตรงกลาง)

หลักการออกแบบ:
- **น่าเชื่อถือแบบสถาบันการศึกษา** — ไม่ใช้สีฉูดฉาดเกินความจำเป็น ใช้แดง/ทองเป็นสีเน้น (accent) ไม่ใช่สีพื้นหลังหลักของทั้งหน้าจอ
- **อ่านง่ายก่อนสวยงาม** — เนื้อหาเกี่ยวกับผลการเรียนและความเสี่ยงต้องอ่านและเข้าใจได้เร็ว คอนทราสต์ต้องผ่านเกณฑ์ accessibility เสมอ (ดู [[#4.4 การเข้าถึง (Accessibility)]])
- **สงบ ไม่สร้างความตื่นตระหนก** — แม้ระบบจะแจ้งเตือน "ความเสี่ยง" แต่โทนสีและถ้อยคำต้องให้ความรู้สึกสนับสนุน ไม่ตัดสิน (ดู [[#4.2 Tone of Voice]])

### 1.2 การใช้งานโลโก้

- ใช้โลโก้มหาวิทยาลัยแม่ฟ้าหลวงเฉพาะในบริบทที่เกี่ยวข้องกับสถาบัน (เช่น หน้า login, footer, เอกสารทางการ) — **ห้ามดัดแปลงสัดส่วน สี หรือองค์ประกอบของโลโก้**
- พื้นหลังรองรับโลโก้: ใช้ได้ทั้งบนพื้นขาว (`--color-neutral-0`) และพื้นแดงเข้ม (`--color-primary-700`) ตามต้นฉบับ ห้ามวางโลโก้บนพื้นสีอื่นที่ทำให้คอนทราสต์ต่ำ
- พื้นที่ว่างรอบโลโก้ (clear space) ต้องไม่น้อยกว่าความสูงของยอดเจดีย์ในโลโก้ ไม่วางข้อความหรือองค์ประกอบอื่นซ้อนทับ
- โลโก้ผลิตภัณฑ์ (Grade Runway) ที่ยังไม่ถูกออกแบบ ให้ใช้ wordmark ตัวอักษร (typography-based) โดยใช้สีจาก token `--color-primary-600` เป็นการชั่วคราว จนกว่าจะมีเอกสาร brand mark แยกต่างหาก

### 1.3 การใช้สีในบริบท CI

| บริบท | สีที่ใช้ |
|---|---|
| Header / navigation bar หลัก | `--color-primary-700` (แดงเลือดหมูเข้ม) พื้นหลัง, ตัวอักษรสีขาว |
| ปุ่มหลัก (primary action) | `--color-primary-600` |
| จุดเน้น/ไฮไลต์พิเศษ (badge ความสำเร็จ, มงกุฎ mentor) | `--color-accent-gold-500` |
| พื้นหลังทั่วไปของแอป | `--color-neutral-0` / `--color-neutral-50` |
| ข้อความหลัก | `--color-neutral-900` |

## 2. Design Tokens

### 2.1 Colors

โทนสีอ้างอิงจากโลโก้มหาวิทยาลัยแม่ฟ้าหลวง (พื้นแดงเลือดหมู + ทอง) ค่า hex ด้านล่างเป็นค่าประมาณจากภาพโลโก้ที่แนบ ให้ทีมออกแบบยืนยันกับคู่มือ CI ฉบับทางการของมหาวิทยาลัยอีกครั้งก่อนใช้งานจริงในโปรดักชัน

#### Primary — Maroon Red (จากพื้นโลโก้)

| Token | Hex | การใช้งาน |
|---|---|---|
| `--color-primary-900` | `#3D0A0D` | ข้อความ/ไอคอนบนพื้นสว่างที่ต้องการน้ำหนักสูงสุด |
| `--color-primary-700` | `#6E1116` | Header, navigation bar, พื้นหลังโลโก้ |
| `--color-primary-600` | `#8B1A1F` | ปุ่มหลัก, ลิงก์เน้น, สถานะ active |
| `--color-primary-500` | `#A6222A` | Hover state ของปุ่มหลัก |
| `--color-primary-100` | `#F3D9DA` | พื้นหลัง badge/แจ้งเตือนแบบอ่อน (เช่น แถบความเสี่ยงระดับต่ำ) |
| `--color-primary-50` | `#FBEFEF` | พื้นหลัง section เน้นเบา ๆ |

#### Accent — Gold (จากลวดลายเจดีย์/ริบบิ้นในโลโก้)

| Token | Hex | การใช้งาน |
|---|---|---|
| `--color-accent-gold-700` | `#8A6A16` | ข้อความบนพื้นทองอ่อน (ต้องคอนทราสต์พออ่านได้) |
| `--color-accent-gold-500` | `#C9A227` | ไอคอน/แบดจ์เกียรติยศ (เช่น สถานะ mentor เกรดสูง), เส้นขอบเน้น |
| `--color-accent-gold-300` | `#E4C877` | Hover/พื้นหลังรองของ badge ทอง |
| `--color-accent-gold-100` | `#F8ECC7` | พื้นหลังอ่อนสำหรับ highlight เนื้อหาแนะนำ |

#### Neutral — Grayscale

| Token | Hex | การใช้งาน |
|---|---|---|
| `--color-neutral-900` | `#1F1B1B` | ข้อความหลัก |
| `--color-neutral-700` | `#4A4444` | ข้อความรอง/label |
| `--color-neutral-500` | `#8A8282` | ข้อความ disabled, placeholder |
| `--color-neutral-300` | `#D9D3D3` | เส้นขอบ (border), divider |
| `--color-neutral-100` | `#F1EDED` | พื้นหลัง card, พื้นหลังสำรอง |
| `--color-neutral-50` | `#FAF8F8` | พื้นหลังหน้าเว็บโดยรวม |
| `--color-neutral-0` | `#FFFFFF` | พื้นหลัง card หลัก, พื้นหลังสำหรับโลโก้ |

> หมายเหตุ: โทนกลาง (neutral) ผสมโทนอุ่นเล็กน้อย (warm gray) ให้เข้ากับโทนแดง/ทองของแบรนด์ แทนที่จะใช้เกรย์เย็น (cool gray) ตรง ๆ

#### Semantic Colors

ระบบนี้มีฟีเจอร์แจ้งเตือนความเสี่ยงทางการเรียน ([[01-prototypes/20260827-01-features-list-personalized-learning-reminder|Features List: ระบบเตือนฯ]]) จึงต้องมีชุดสีสถานะที่ชัดเจน **แยกออกจากสี primary/accent ของแบรนด์** เพื่อไม่ให้ผู้ใช้สับสนระหว่าง "สีแบรนด์" กับ "สีเตือนความเสี่ยง"

| Token | Hex | ความหมาย | ตัวอย่างการใช้ |
|---|---|---|---|
| `--color-success-500` | `#2E7D46` | ปกติ / ผ่านเกณฑ์ / สำเร็จ | แถบสถานะ "อยู่ในเกณฑ์ปกติ", ข้อความยืนยันการส่งงานสำเร็จ |
| `--color-warning-500` | `#C77B12` | ความเสี่ยงระดับต้องเฝ้าระวัง | แจ้งเตือนแนวโน้มเกรดลดลง, ใกล้เกณฑ์ขาดเรียน |
| `--color-danger-500` | `#B3261E` | ความเสี่ยงระดับสูง / ต้องดำเนินการ | เข้าเงื่อนไขความเสี่ยงหลายตัวแปรพร้อมกัน |
| `--color-info-500` | `#2F6FA6` | ข้อมูลทั่วไป / เป็นกลาง | สรุปภาพรวมรายสัปดาห์, ข้อความระบบทั่วไป |

**กฎสำคัญ:** `--color-danger-500` ต้องไม่ใช้ค่าเดียวกับ `--color-primary-600` แม้จะอยู่ในโทนแดงใกล้เคียงกัน เพื่อให้แยกแยะได้ว่าสีแดงนั้นคือ "แบรนด์" หรือ "คำเตือน" — แนะนำให้ทดสอบคู่สีทั้งสองเคียงกันในหน้าจอจริงก่อนใช้งาน

### 2.2 Typography

#### Font Family

- **ภาษาไทย + ละติน:** `Noto Sans Thai` (หลัก) โดยมี fallback เป็น `Sarabun` และ system font (`-apple-system, "Segoe UI", Roboto, sans-serif`)
- **ตัวเลข/โค้ด (เช่น เกรด, เปอร์เซ็นต์การเข้าเรียน):** ใช้ font ตัวเลขแบบ tabular (`font-variant-numeric: tabular-nums`) เพื่อให้ตัวเลขในตารางเรียงชิดกันสวยงาม ไม่ใช้ monospace เต็มรูปแบบ

```css
--font-family-base: "Noto Sans Thai", "Sarabun", -apple-system, "Segoe UI", Roboto, sans-serif;
```

#### Type Scale

| Token | ขนาด (px / rem) | น้ำหนัก | การใช้งาน |
|---|---|---|---|
| `--font-size-display` | 32px / 2rem | 700 (Bold) | หัวข้อหน้าหลัก (เช่น "ภาพรวมผลการเรียน") |
| `--font-size-h1` | 24px / 1.5rem | 700 | หัวข้อ section ใหญ่ |
| `--font-size-h2` | 20px / 1.25rem | 600 (Semibold) | หัวข้อ card / หัวข้อย่อย |
| `--font-size-h3` | 16px / 1rem | 600 | หัวข้อภายใน component |
| `--font-size-body` | 14px / 0.875rem | 400 (Regular) | เนื้อหาทั่วไป, ข้อความในฟอร์ม |
| `--font-size-body-lg` | 16px / 1rem | 400 | เนื้อหาสำคัญที่ต้องอ่านง่าย (เช่น คำแนะนำการเรียนเฉพาะบุคคล) |
| `--font-size-caption` | 12px / 0.75rem | 400 | label, timestamp, ข้อความช่วยอธิบาย (helper text) |
| `--font-size-overline` | 11px / 0.6875rem | 600, uppercase, letter-spacing 0.04em | ป้ายกำกับหมวดหมู่ (เช่น "รายวิชา", "สถานะ") |

- **Line height:** ใช้ 1.5 สำหรับเนื้อหาย่อหน้า (`--line-height-body`), 1.3 สำหรับหัวข้อ (`--line-height-heading`)
- **ห้ามใช้ font-weight ต่ำกว่า 400** กับข้อความบนพื้นสี (เช่นบนปุ่ม primary) เพราะอ่านยากเมื่อคอนทราสต์ต่ำ

### 2.3 Spacing

ใช้ระบบ spacing แบบ 4px base scale เพื่อให้จัดวางองค์ประกอบสอดคล้องกันทั้งระบบ

| Token | ค่า |
|---|---|
| `--space-1` | 4px |
| `--space-2` | 8px |
| `--space-3` | 12px |
| `--space-4` | 16px |
| `--space-5` | 24px |
| `--space-6` | 32px |
| `--space-7` | 48px |
| `--space-8` | 64px |

- Padding ภายใน component (เช่นปุ่ม, input): ใช้ `--space-2` ถึง `--space-4`
- ระยะห่างระหว่าง section: ใช้ `--space-6` ขึ้นไป
- ระยะห่างระหว่าง card ในรายการ (list/grid): ใช้ `--space-4`

## 3. UI Components & Patterns

หมวดนี้ครอบคลุมคอมโพเนนต์หลักที่ใช้ร่วมกันในทุกฟีเจอร์ โดยอ้างอิงความต้องการใช้งานจริงจาก [[01-prototypes/index|01-prototypes]] (ระบบแจ้งเตือน/คำแนะนำการเรียน และห้องแชทรีวิว)

### 3.1 ปุ่ม (Buttons)

| Variant | พื้นหลัง | ข้อความ | เมื่อใช้ |
|---|---|---|---|
| Primary | `--color-primary-600` | ขาว | Action หลักของหน้า (เช่น "ส่งคำขอเป็นผู้แนะนำ") |
| Secondary | โปร่งใส, ขอบ `--color-primary-600` | `--color-primary-600` | Action รอง (เช่น "ยกเลิก") |
| Danger | `--color-danger-500` | ขาว | Action ที่มีผลกระทบ (เช่น "ลบข้อความ", "ระงับสิทธิ์ผู้แนะนำ") — ใช้เฉพาะบริบทที่ผู้ดูแลระบบดำเนินการ |
| Ghost/Text | โปร่งใส | `--color-neutral-700` | Action เสริมที่ไม่ต้องการเน้น (เช่น "ดูเพิ่มเติม") |

กฎ: ปุ่ม disabled ใช้ `--color-neutral-300` เป็นพื้นหลังและ `--color-neutral-500` เป็นข้อความเสมอ ไม่ลดความทึบ (opacity) ของสีปุ่มปกติ เพราะจะทำให้คอนทราสต์ตกเกณฑ์ accessibility

### 3.2 การ์ด (Cards)

ใช้สำหรับแสดงข้อมูลผลการเรียนแบบสรุป, รายการ mentor, หรือ item ในสรุปรายสัปดาห์
- พื้นหลัง `--color-neutral-0`, ขอบมน `--radius-md`, เงา `--shadow-sm`
- หัวการ์ดใช้ `--font-size-h2` ตามด้วยเนื้อหาแบบ `--font-size-body`
- การ์ดที่สื่อถึงระดับความเสี่ยง ให้ใช้แถบสี (left border 4px) ด้วย semantic color ที่สอดคล้อง (`--color-success-500` / `--color-warning-500` / `--color-danger-500`) แทนการเปลี่ยนสีพื้นหลังทั้งการ์ด เพื่อไม่ให้ตัวหนังสือภายในอ่านยาก

### 3.3 Badge / Status Tag

ใช้แสดงสถานะสั้น ๆ เช่น ระดับความเสี่ยง, สถานะข้อความในห้องแชท (รอตรวจ/อนุมัติแล้ว/ถูกปฏิเสธ), สถานะผู้แนะนำ

| สถานะ | สี |
|---|---|
| ปกติ / อนุมัติแล้ว | พื้นหลัง `--color-success-500` โทนอ่อน 10% + ข้อความ `--color-success-500` |
| ต้องเฝ้าระวัง / รอตรวจ (pending moderation) | พื้นหลัง `--color-warning-500` โทนอ่อน 10% + ข้อความ `--color-warning-500` |
| ความเสี่ยงสูง / ถูกปฏิเสธ | พื้นหลัง `--color-danger-500` โทนอ่อน 10% + ข้อความ `--color-danger-500` |
| ผู้แนะนำเกรดสูง (mentor) | พื้นหลัง `--color-accent-gold-100` + ข้อความ `--color-accent-gold-700` + ไอคอนดาว/มงกุฎสีทอง |

รูปร่าง: pill (`--radius-full`), padding `--space-1` × `--space-3`, ตัวอักษร `--font-size-caption` น้ำหนัก 600

### 3.4 การแจ้งเตือน (Notifications & Alerts)

รองรับ [[01-prototypes/20260827-01-features-list-personalized-learning-reminder|ระบบเตือนและแนะนำแนวทางการเรียนส่วนบุคคล]] โดยแบ่งรูปแบบตามความเร่งด่วน

- **In-app toast** (แจ้งเตือนทันทีที่เข้าเงื่อนไขความเสี่ยง): แสดงมุมบนขวา, ใช้ semantic color ตามระดับความเสี่ยง, หายไปเองใน 6 วินาที ยกเว้นระดับ danger ให้ผู้ใช้ต้องกดปิดเอง
- **Inline banner** (สรุปภาพรวมรายสัปดาห์): แสดงบนสุดของหน้า dashboard ใช้พื้นหลัง `--color-info-500` โทนอ่อน ไม่ auto-dismiss
- **Notification center / list**: รายการแจ้งเตือนย้อนหลัง เรียงใหม่→เก่า แต่ละแถวมี icon สถานะ + timestamp (`--font-size-caption`, สี `--color-neutral-500`)

กฎสำคัญ: ห้ามใช้ `--color-danger-500` ล้วนเป็นพื้นหลังเต็มพื้นที่ของ toast/banner (จะดูก้าวร้าวเกินไปสำหรับข้อความที่มีเจตนาสนับสนุนผู้เรียน) ให้ใช้เป็นสีขอบ/ไอคอน/ข้อความแทน โดยพื้นหลังยังคงเป็นโทนอ่อน

### 3.5 Chat / Message Bubble

รองรับฟีเจอร์ห้องแชทรีวิวจากนักศึกษาเกรดสูง ([[01-prototypes/20260827-03-features-list-high-grade-peer-review-chat|Features List: ช่องแชทรีวิวฯ]])

- ข้อความของผู้ใช้เอง: ชิดขวา, พื้นหลัง `--color-primary-100`, ตัวอักษร `--color-neutral-900`
- ข้อความของผู้อื่น: ชิดซ้าย, พื้นหลัง `--color-neutral-100`
- ข้อความจาก mentor ที่ได้รับอนุมัติ: เพิ่ม badge ทอง (ดู 3.3) กำกับชื่อผู้ส่ง เพื่อให้แยกจากข้อความทั่วไปได้ทันที
- ข้อความที่อยู่ระหว่างรอ pre-moderation (ยังไม่แสดงต่อสาธารณะ): แสดงเฉพาะฝั่งผู้ส่งเห็น พร้อม badge "รอตรวจ" (`--color-warning-500`) และ label กำกับชัดเจนว่า "รอการตรวจสอบ — ยังไม่เผยแพร่"
- Radius ของ bubble: `--radius-lg` ยกเว้นมุมด้านผู้ส่ง (มุมล่างขวา/ซ้าย) ใช้ `--radius-sm` ตามรูปแบบ chat ทั่วไป

### 3.6 ฟอร์มและ Input

- Input, textarea, select ใช้ขอบ `--color-neutral-300`, radius `--radius-sm`, เมื่อ focus เปลี่ยนขอบเป็น `--color-primary-600` หนา 2px
- ข้อความ error ใต้ input ใช้ `--color-danger-500`, `--font-size-caption`
- Label ของฟอร์มอยู่เหนือ input เสมอ (ไม่ใช้ placeholder แทน label) เพื่อความชัดเจนสำหรับผู้ใช้ทุกกลุ่ม

### 3.7 Navigation

- Top navigation bar: พื้นหลัง `--color-primary-700`, โลโก้/ชื่อระบบชิดซ้าย, เมนูผู้ใช้ชิดขวา
- Active menu item: ขีดเส้นใต้ `--color-accent-gold-500` หนา 2px เพื่อให้เห็นสถานะ active ชัดเจนแบบเดียวกับสัญลักษณ์ทองในโลโก้ ไม่ใช้การเปลี่ยนสีพื้นหลังทั้งปุ่มเมนู

## 4. UX Guidelines & Rules

### 4.1 หลักการออกแบบโดยรวม

- **แสดงข้อมูลความเสี่ยงแบบสร้างสรรค์ ไม่ตัดสิน** — ทุกจุดที่แสดงสถานะความเสี่ยง (warning/danger) ต้องมีคำแนะนำแนวทางแก้ไขอยู่ใกล้กันเสมอ ห้ามแสดงป้าย "เสี่ยง" ลอย ๆ โดยไม่มี context หรือทางออก
- **Configurable ต้องสะท้อนใน UI** — เนื่องจากเกณฑ์ความเสี่ยงเป็นค่าที่ผู้ดูแลระบบปรับได้ ([[../01-requirements/01-spec/20260825-01-personalized-learning-reminder|spec: ระบบเตือนฯ]]) หน้าจอที่เกี่ยวข้องต้องไม่ hardcode ข้อความอธิบายเกณฑ์ (เช่น "ขาดเรียนเกิน 3 ครั้ง") แต่ต้องดึงค่าจริงจากการตั้งค่าปัจจุบันมาแสดงเสมอ
- **ความโปร่งใสของสถานะการตรวจสอบ (moderation)** — ผู้ส่งข้อความในห้องแชทต้องเห็นสถานะข้อความของตัวเองชัดเจนทุกขั้น (รอตรวจ/อนุมัติ/ปฏิเสธ) ไม่ปล่อยให้ข้อความหายไปเงียบ ๆ

### 4.2 Tone of Voice

- ใช้ภาษาที่ **สุภาพ ให้กำลังใจ ไม่กล่าวโทษ** เช่น ใช้ "ผลการเรียนช่วงนี้มีแนวโน้มลดลง ลองดูคำแนะนำนี้นะ" แทน "คุณกำลังจะสอบตก"
- คำแนะนำการเรียนเฉพาะบุคคลต้องเขียนในมุมมองที่ **actionable** (บอกว่าควรทำอะไรต่อ) ไม่ใช่แค่บอกปัญหา
- ข้อความในห้องแชทฝั่งแอดมิน/ระบบ (เช่น แจ้งปฏิเสธข้อความ) ต้องระบุเหตุผลสั้น ๆ เสมอ ไม่ใช้ข้อความสำเร็จรูปที่ไม่สื่อความ เช่น "ไม่ผ่านการตรวจสอบ"

### 4.3 Responsive & Layout Rules

- ออกแบบแบบ **mobile-first** เนื่องจากกลุ่มผู้ใช้หลักคือนักเรียน/นักศึกษาที่ใช้งานผ่านมือถือเป็นหลัก
- Layout หลักใช้ 12-column grid บน desktop (`--bp-desktop`), ยุบเป็น single column บนมือถือ (`--bp-mobile`)
- Navigation บนมือถือใช้ bottom tab bar แทน top navigation เต็มรูปแบบ เพื่อให้กดถึงเมนูหลักได้ด้วยนิ้วโป้งสะดวก

### 4.4 การเข้าถึง (Accessibility)

- คู่สีข้อความ/พื้นหลังทุกคู่ต้องผ่านเกณฑ์ **WCAG 2.1 AA** (contrast ratio ≥ 4.5:1 สำหรับข้อความปกติ, ≥ 3:1 สำหรับข้อความขนาดใหญ่/หัวข้อ) — โดยเฉพาะคู่สี `--color-primary-600` บนพื้นขาว และตัวอักษรบน badge ทอง (`--color-accent-gold-700` บน `--color-accent-gold-100`) ที่ต้องตรวจสอบเป็นพิเศษเพราะโทนสีใกล้เคียงกัน
- **ห้ามสื่อสถานะด้วยสีเพียงอย่างเดียว** — ทุกจุดที่ใช้ semantic color (success/warning/danger) ต้องมี icon หรือข้อความกำกับควบคู่เสมอ เพื่อรองรับผู้ใช้ที่มีภาวะตาบอดสี
- ทุก interactive element (ปุ่ม, input, การ์ดที่กดได้) ต้องมี focus state ที่มองเห็นชัดเจนสำหรับการใช้งานผ่านคีย์บอร์ด
- ขนาดพื้นที่กดขั้นต่ำ (touch target) บนมือถือ: 44×44px

### 4.5 Empty State & Error State

- ทุกหน้าที่แสดงรายการ (เช่น รายการแจ้งเตือน, รายการห้องแชท) ต้องออกแบบ empty state ที่บอกสาเหตุและขั้นตอนถัดไป ไม่ใช่ปล่อยพื้นที่ว่างเปล่า
- ข้อความ error ต้องบอกสาเหตุและวิธีแก้ที่ทำได้จริง หลีกเลี่ยงข้อความ error ทั่วไปแบบ "เกิดข้อผิดพลาด" โดยไม่มีรายละเอียดเพิ่มเติม
