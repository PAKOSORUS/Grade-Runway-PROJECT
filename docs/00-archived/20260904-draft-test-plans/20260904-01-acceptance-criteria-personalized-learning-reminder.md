# Acceptance Criteria: ระบบเตือนและแนะนำแนวทางการเรียนส่วนบุคคล

**สร้างจาก:** [[../../01-requirements/01-spec/20260825-01-personalized-learning-reminder|ระบบเตือนและแนะนำแนวทางการเรียนส่วนบุคคล]]
**เกี่ยวข้องกับ:** [[../../02-design/01-prototypes/20260827-01-features-list-personalized-learning-reminder|Features List]], [[../../02-design/01-prototypes/20260827-02-user-journey-student-personalized-learning-reminder|User Journey: นักเรียน/นักศึกษา]]
**วันที่สร้าง:** 2026-09-04

## Acceptance Criteria ต่อ User Story

### AC-1: ตรวจจับความเสี่ยงจากหลายตัวแปรและแจ้งเตือนแบบ in-app ทันที
**อ้างอิง User Story:** "ในฐานะนักเรียน/นักศึกษา ฉันต้องการได้รับการแจ้งเตือนเมื่อผลการเรียนหรือพฤติกรรมการเรียนของฉันเข้าเงื่อนไขที่มีความเสี่ยง เพื่อที่จะปรับตัวได้ทันเวลาก่อนปัญหาลุกลาม" (BR1, BR4)

- **Given** นักเรียน/นักศึกษามีข้อมูลผลการเรียน การเข้าเรียน การส่งงาน และแนวโน้มผลการเรียนสะสมอยู่ในระบบ
- **When** ค่าตัวแปรใดตัวแปรหนึ่งต่อไปนี้เข้าเงื่อนไขเกณฑ์ที่ผู้ดูแลระบบกำหนดไว้: (ก) เกรด/ผลการเรียนต่ำกว่าเกณฑ์, (ข) อัตราการขาดเรียนเกินเกณฑ์, (ค) ไม่ส่งงาน/ไม่ทำแบบทดสอบเกินจำนวนที่กำหนด, หรือ (ง) แนวโน้มผลการเรียนลดลงต่อเนื่องหลายช่วงเวลา
- **Then** ระบบต้องส่งการแจ้งเตือนแบบ in-app ให้ผู้เรียนคนนั้นทันทีที่ตรวจพบเงื่อนไข (BR4) โดยไม่ต้องรอรอบสรุปรายสัปดาห์
- **Given** เกณฑ์ของแต่ละตัวแปรถูกกำหนดค่าไว้แบบ configurable โดยผู้ดูแลระบบ (BR2)
  - **When** ค่าตัวแปรของผู้เรียนยังไม่ถึงเกณฑ์ที่กำหนดไว้ (ไม่ว่าตัวแปรใด)
  - **Then** ระบบต้องไม่ส่งการแจ้งเตือนความเสี่ยงสำหรับตัวแปรนั้น
- **Edge case (จาก user journey):** เมื่อผู้เรียนเข้าเงื่อนไขเสี่ยงหลายตัวแปรพร้อมกันในเวลาเดียวกัน ระบบต้องแจ้งเตือนครบทุกตัวแปรที่เข้าเงื่อนไข ไม่ตกหล่นสักตัว _(ลำดับ/การจัดกลุ่มการแจ้งเตือนหลายตัวแปรพร้อมกัน — ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_

### AC-2: คำแนะนำแนวทางการเรียนเฉพาะบุคคล
**อ้างอิง User Story:** "ในฐานะนักเรียน/นักศึกษา ฉันต้องการเห็นคำแนะนำแนวทางการเรียนที่คำนวณเฉพาะสำหรับฉันจากข้อมูลผลการเรียนย้อนหลัง เพื่อให้คำแนะนำตรงกับสถานการณ์จริงของฉัน ไม่ใช่คำแนะนำสำเร็จรูปเดียวกันสำหรับทุกคน" (BR3)

- **Given** ผู้เรียนได้รับการแจ้งเตือนว่าเข้าเงื่อนไขความเสี่ยง (ตาม AC-1) และมีข้อมูลผลการเรียน/พฤติกรรมย้อนหลังสะสมเพียงพอในระบบ
- **When** ผู้เรียนเปิดดูคำแนะนำแนวทางการเรียนของตัวเอง
- **Then** ระบบต้องแสดงคำแนะนำที่คำนวณจากข้อมูลย้อนหลังเฉพาะของผู้เรียนคนนั้น (เช่น อิงจากรายวิชา/ตัวแปรที่เข้าเงื่อนไขจริงของผู้เรียนคนนั้น) และคำแนะนำของผู้เรียนสองคนที่มีสถานการณ์ต่างกันต้องไม่เหมือนกันทุกตัวอักษร (ไม่ใช่ template สำเร็จรูปเดียวกันสำหรับทุกคน)
- **Edge case (จาก user journey):** เมื่อผู้เรียนเพิ่งเข้าเรียนและยังไม่มีข้อมูลย้อนหลังเพียงพอสำหรับคำนวณคำแนะนำเฉพาะบุคคล ระบบต้องไม่เกิด error และต้องแสดงข้อความที่สื่อสารอย่างชัดเจนว่ายังไม่สามารถให้คำแนะนำเฉพาะบุคคลได้ในขณะนี้ _(รูปแบบ fallback ที่แน่นอน — spec ไม่ได้ระบุ ต้องการข้อมูลเพิ่มเติมจากผู้ใช้ สมมติฐานที่ใช้ในการร่าง: ระบบต้อง degrade gracefully ไม่ error)_

### AC-3: สรุปภาพรวมสถานการณ์การเรียนรายสัปดาห์
**อ้างอิง User Story:** "ในฐานะนักเรียน/นักศึกษา ฉันต้องการเห็นสรุปภาพรวมสถานการณ์การเรียนของตัวเองแบบรายสัปดาห์ นอกเหนือจากการแจ้งเตือนแบบทันที" (BR4)

- **Given** ผู้เรียนมีข้อมูลผลการเรียน/พฤติกรรมสะสมในระบบมาแล้วอย่างน้อยหนึ่งสัปดาห์
- **When** ถึงรอบสรุปภาพรวมรายสัปดาห์ (หรือผู้เรียนเปิดดูหน้าสรุปรายสัปดาห์ด้วยตัวเอง)
- **Then** ระบบต้องแสดงสรุปภาพรวมสถานการณ์การเรียนของสัปดาห์นั้นให้ผู้เรียนเห็น โดยไม่ขึ้นกับว่าผู้เรียนได้รับการแจ้งเตือนแบบทันทีในสัปดาห์นั้นหรือไม่ (สรุปรายสัปดาห์เป็นช่องทางแยกต่างหากจากการแจ้งเตือนทันที)
- _(รายละเอียดเนื้อหาภายในสรุปรายสัปดาห์ เช่น การเปรียบเทียบกับสัปดาห์ก่อนหน้า — spec ไม่ได้ระบุไว้ ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_

### AC-4: ผู้ดูแลระบบปรับแต่งเกณฑ์/ตัวแปรที่ใช้ในการแจ้งเตือน
**อ้างอิง User Story:** "ในฐานะผู้ดูแลระบบ ฉันต้องการปรับแต่งเกณฑ์/ตัวแปรที่ใช้ในการแจ้งเตือนได้ เพื่อให้ระบบยืดหยุ่นพอจะนำไปปรับใช้กับบริบทอื่นได้ในอนาคต" (BR2)

- **Given** ผู้ดูแลระบบเข้าสู่หน้าจัดการเกณฑ์/ตัวแปรสำหรับการแจ้งเตือน
- **When** ผู้ดูแลระบบแก้ไขค่าเกณฑ์ของตัวแปรใดตัวแปรหนึ่ง (เช่น เกณฑ์เกรด, เกณฑ์อัตราขาดเรียน, เกณฑ์จำนวนงานที่ไม่ส่ง, จำนวนช่วงเวลาที่นับว่าแนวโน้มลดลงต่อเนื่อง) แล้วบันทึก
- **Then** ระบบต้องบันทึกค่าที่แก้ไขและใช้ค่าใหม่นี้ในการประเมินความเสี่ยงของผู้เรียนตั้งแต่รอบการประเมินถัดไปเป็นต้นไป โดยไม่ต้อง hardcode ค่าตายตัวในโค้ด (BR2)
- **When** ผู้ดูแลระบบพยายามบันทึกค่าเกณฑ์ที่ไม่ถูกต้อง (เช่น ค่าติดลบ, ค่าว่าง, รูปแบบข้อมูลไม่ถูกต้อง)
- **Then** ระบบต้องปฏิเสธการบันทึกและแจ้งข้อผิดพลาดให้ผู้ดูแลระบบทราบ โดยไม่กระทบเกณฑ์เดิมที่ใช้งานอยู่
- **Edge case (จาก user journey):** เมื่อผู้ดูแลระบบเปลี่ยนเกณฑ์ระหว่างที่มีการแจ้งเตือนของผู้เรียนบางคนค้างอยู่ (ยังไม่ได้อ่าน) _(ผลกระทบต่อการแจ้งเตือนที่ค้างอยู่ — spec ไม่ได้ระบุ ต้องการข้อมูลเพิ่มเติมจากผู้ใช้)_
