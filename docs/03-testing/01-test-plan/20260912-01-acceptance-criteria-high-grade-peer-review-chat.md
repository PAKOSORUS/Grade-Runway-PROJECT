# Acceptance Criteria: ช่องแชทรีวิวและแนะนำวิธีการเรียนจากนักศึกษาเกรดสูง

## Acceptance Criteria ต่อ User Story

### AC-1: ระบบเสนอชื่อผู้แนะนำอัตโนมัติจากเกณฑ์ผลการเรียน
**อ้างอิง User Story (US3):** "ในฐานะระบบ ฉันต้องการประมวลผลรายชื่อนักศึกษาที่เข้าเกณฑ์ผลการเรียนสูงในแต่ละวิชา แล้วเสนอชื่อ (suggest) ให้ผู้ดูแลระบบพิจารณาอนุมัติเป็นผู้แนะนำ/ผู้รีวิวประจำห้องแชทนั้น" (BR1 ข้อ 1)

- **Given** นักศึกษาลงทะเบียนวิชา A ในภาคปัจจุบัน และมีเกรด/GPA ถึงเกณฑ์ที่แอดมินตั้งค่าไว้สำหรับวิชา A
- **When** ระบบประมวลผลผลการเรียนรอบล่าสุด
- **Then** ระบบต้องขึ้นชื่อนักศึกษาคนนั้นในคิวอนุมัติผู้แนะนำของวิชา A พร้อมค่าเกรด/GPA จริงเทียบกับเกณฑ์ปัจจุบัน โดยยังไม่ให้สิทธิ์ผู้แนะนำทันที (BR1 ข้อ 2 — ต้องรอแอดมินอนุมัติก่อน)

- **Given** นักศึกษาลงทะเบียนวิชา A แต่เกรด/GPA ยังไม่ถึงเกณฑ์ที่ตั้งค่าไว้
- **When** ระบบประมวลผลผลการเรียนรอบล่าสุด
- **Then** ระบบต้องไม่เสนอชื่อนักศึกษาคนนั้นเข้าคิวอนุมัติผู้แนะนำของวิชา A

- **Edge case (แอดมินเปลี่ยนค่าเกณฑ์):**
  - **Given** แอดมินปรับค่าเกณฑ์เกรด/GPA ของวิชา A ผ่านหน้าตั้งค่าเกณฑ์
  - **When** ระบบประมวลผลรอบถัดไป
  - **Then** ระบบต้องใช้ค่าเกณฑ์ใหม่ในการพิจารณาเสนอชื่อ (ดึงค่าจริงจากการตั้งค่า ไม่ hardcode) _(สมมติฐาน: ไม่กระทบสิทธิ์ที่อนุมัติไปแล้วก่อนเปลี่ยนเกณฑ์ — spec ยังไม่ระบุตรงนี้)_

---

### AC-2: แอดมินยืนยันความเหมาะสมของผู้แนะนำก่อนให้สิทธิ์จริง
**อ้างอิง User Story (US4):** "ในฐานะผู้ดูแลระบบ ฉันต้องการตรวจสอบและยืนยันความเหมาะสม (approve) ของรายชื่อที่ระบบเสนอมา ก่อนที่นักศึกษาคนนั้นจะได้รับสิทธิ์เป็นผู้แนะนำในห้องแชท" (BR1 ข้อ 2)

- **Given** มีรายชื่อนักศึกษารอการอนุมัติในคิวอนุมัติผู้แนะนำของวิชา A
- **When** แอดมินกด "อนุมัติ" สำหรับรายชื่อนั้น
- **Then** นักศึกษาคนนั้นต้องได้รับสิทธิ์ผู้แนะนำ (mentor role) ของวิชา A ทันที, เห็น badge ทองในห้องแชทของวิชานั้น, และได้รับแจ้งสถานะ "ได้รับสิทธิ์แล้ว" ในหน้าสถานะของตนเอง

- **Given** มีรายชื่อนักศึกษารอการอนุมัติในคิวอนุมัติผู้แนะนำของวิชา A
- **When** แอดมินกด "ปฏิเสธ" สำหรับรายชื่อนั้น
- **Then** นักศึกษาคนนั้นต้องไม่ได้รับสิทธิ์ผู้แนะนำ และสถานะของตนเองต้องเปลี่ยนเป็น "ถูกปฏิเสธ" _(สมมติฐานตาม wireframe: ต้องกรอกเหตุผลสั้นๆ ก่อนยืนยันปฏิเสธ และแสดงเหตุผลนั้นให้นักศึกษาเห็น — spec ไม่ได้ระบุตรงๆ)_

- **Given** ระบบยังไม่เคยเสนอชื่อนักศึกษาคนใดในวิชาที่นักศึกษากำลังดูอยู่
- **When** นักศึกษาเปิดหน้าสถานะสิทธิ์ผู้แนะนำของตนเอง
- **Then** ต้องแสดงข้อความอธิบายว่ายังไม่ถูกเสนอชื่อและระบบจะประมวลผลเมื่อผลการเรียนถึงเกณฑ์ ไม่ใช่หน้าว่างเปล่า

---

### AC-3: ห้องแชทแยกตามรายวิชาและจำกัดการเข้าถึงตามการลงทะเบียนภาคปัจจุบัน
**อ้างอิง User Story (US1, US2):** ทั้งผู้แนะนำและนักศึกษาทั่วไปต้องเข้าห้องแชท "ของรายวิชาที่ฉันเรียนอยู่" (BR2 — แยกห้องตามรายวิชา, BR3 — จำกัดสิทธิ์เข้าถึงตามการลงทะเบียนภาคปัจจุบัน)

- **Given** นักศึกษาลงทะเบียนเรียนวิชา A ในภาคการศึกษาปัจจุบัน
- **When** นักศึกษาเปิดรายการห้องแชทของตน
- **Then** ต้องเห็นห้องแชทของวิชา A เท่านั้น (ไม่เห็นห้องแชทของวิชาที่ตนไม่ได้ลงทะเบียน) และเข้าอ่าน/สนทนาในห้องนั้นได้ตามปกติ

- **Given** นักศึกษาไม่ได้ลงทะเบียนเรียนวิชา B ในภาคปัจจุบัน
- **When** นักศึกษาพยายามเข้าห้องแชทของวิชา B (เช่น ผ่านลิงก์ตรง)
- **Then** ระบบต้องปฏิเสธการเข้าถึงพร้อมข้อความอธิบายสาเหตุที่ชัดเจน (ไม่ใช่หน้าเปล่าหรือ error ทั่วไป) ตาม BR3

- **Edge case (วิชายังไม่มีผู้แนะนำ):**
  - **Given** วิชา B ยังไม่มีนักศึกษาคนใดผ่านการอนุมัติเป็นผู้แนะนำ
  - **When** นักศึกษาที่ลงทะเบียนวิชา B เปิดห้องแชทของวิชานั้น
  - **Then** ห้องแชทต้องเข้าได้ตามปกติ พร้อมแสดง badge/ข้อความ "ยังไม่มีผู้แนะนำ" และยังคงให้ตั้งคำถามล่วงหน้าได้ _(สมมติฐานตาม wireframe เพื่อไม่ให้ผู้ใช้เจอหน้าว่างเปล่าไร้คำอธิบาย)_

---

### AC-4: ผู้แนะนำโพสต์คำแนะนำในห้องแชทของวิชาที่ตนมีสิทธิ์
**อ้างอิง User Story (US1):** "ในฐานะนักศึกษาที่มีผลการเรียนสูง/ผ่านเกณฑ์ที่ระบบกำหนด ฉันต้องการเข้าไปแนะนำหรือรีวิววิธีการเรียนของฉันในห้องแชทของรายวิชาที่ฉันเรียนอยู่ เพื่อช่วยเหลือเพื่อนนักศึกษาในวิชาเดียวกัน"

- **Given** นักศึกษาได้รับสิทธิ์ผู้แนะนำ (ผ่านการอนุมัติแล้ว) ของวิชา A
- **When** ผู้แนะนำพิมพ์และส่งข้อความคำแนะนำในห้องแชทของวิชา A
- **Then** ข้อความต้องถูกส่งเข้าสถานะ "รอตรวจ" ทันที (เห็นเฉพาะฝั่งผู้ส่ง) โดยยังไม่แสดงต่อนักศึกษาคนอื่นจนกว่าจะผ่านการอนุมัติ (เชื่อมโยงกับ AC-6)

- **Given** ผู้แนะนำที่ได้รับอนุมัติในวิชา A ส่งข้อความในห้องแชทของวิชา A
- **When** ข้อความนั้นแสดงในห้องแชทหลังผ่านการอนุมัติแล้ว
- **Then** ข้อความต้องแสดง badge มงกุฎ/ดาวทอง "ผู้แนะนำ" กำกับชื่อผู้ส่งเสมอ เพื่อให้นักศึกษาคนอื่นแยกแยะได้ว่าเป็นคำแนะนำจากผู้แนะนำที่ผ่านการรับรอง

---

### AC-5: นักศึกษาทั่วไปอ่านและตั้งคำถามในห้องแชท
**อ้างอิง User Story (US2):** "ในฐานะนักศึกษาทั่วไป ฉันต้องการเข้าไปอ่าน/สนทนากับนักศึกษาที่ได้เกรดสูงในห้องแชทของรายวิชาที่ฉันเรียน เพื่อขอคำแนะนำแนวทางการเรียนที่ได้ผลจริงและตรงกับวิชานั้นๆ"

- **Given** นักศึกษาทั่วไปที่ลงทะเบียนวิชา A ในภาคปัจจุบัน เปิดห้องแชทของวิชา A
- **When** นักศึกษาอ่านรายการข้อความในห้อง
- **Then** ต้องเห็นเฉพาะข้อความที่ผ่านการเผยแพร่แล้วทั้งหมด (เรียงเก่า→ใหม่) และไม่เห็นข้อความของผู้อื่นที่ยังรอตรวจ/ถูกปฏิเสธ

- **Given** นักศึกษาทั่วไปพิมพ์คำถามในห้องแชทของวิชา A
- **When** นักศึกษากดส่งคำถาม
- **Then** คำถามต้องเข้าสถานะ "รอตรวจ" เช่นเดียวกับข้อความของผู้แนะนำ (ตีความจาก BR4 "ทุกข้อความ") ก่อนแสดงต่อผู้อื่น

---

### AC-6: การตรวจสอบเนื้อหาก่อนเผยแพร่ (Pre-moderation) ครอบคลุมทุกข้อความ
**อ้างอิง User Story (US5):** "ในฐานะผู้ดูแลระบบ ฉันต้องการตรวจสอบเนื้อหาที่ถูกโพสต์ในห้องแชทก่อนเผยแพร่ เพื่อให้มั่นใจว่าคำแนะนำที่ปรากฏเหมาะสมและเป็นประโยชน์" (BR4)

- **Given** มีข้อความใหม่ (จากผู้แนะนำหรือนักศึกษาทั่วไปก็ตาม) ถูกส่งเข้าห้องแชทวิชาใดๆ
- **When** ข้อความนั้นถูกบันทึกเข้าระบบ
- **Then** ข้อความต้องปรากฏในคิวตรวจสอบก่อนเผยแพร่ของแอดมิน โดยยังไม่แสดงต่อนักศึกษาคนอื่นในห้องแชท จนกว่าแอดมินจะอนุมัติ

- **Given** มีข้อความรอตรวจในคิว
- **When** แอดมินกด "อนุมัติ"
- **Then** ข้อความต้องแสดงในห้องแชทให้สมาชิกห้องทุกคนเห็นทันที และสถานะฝั่งผู้ส่งเปลี่ยนเป็น "เผยแพร่แล้ว"

- **Given** มีข้อความรอตรวจในคิว
- **When** แอดมินกด "ปฏิเสธ"
- **Then** ข้อความต้องไม่แสดงต่อผู้อื่นเลย และผู้ส่งต้องเห็นสถานะ "ถูกปฏิเสธ" พร้อมเหตุผลสั้นๆ กำกับ _(สมมติฐานตาม wireframe/Tone of Voice — spec ไม่ได้ยืนยันตรงๆ ว่าต้องแจ้งเหตุผล)_

- **Edge case (ไม่มีข้อความรอตรวจ):**
  - **Given** ไม่มีข้อความใดค้างอยู่ในคิวตรวจสอบ
  - **When** แอดมินเปิดหน้าคิวตรวจสอบข้อความ
  - **Then** ต้องแสดงข้อความให้กำลังใจว่าไม่มีงานค้าง ไม่ใช่หน้าว่างเปล่าไร้ความหมาย
