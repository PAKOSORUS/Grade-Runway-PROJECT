# Test Plan: ช่องแชทรีวิวและแนะนำวิธีการเรียนจากนักศึกษาเกรดสูง

**สร้างจาก:** [[../../01-requirements/01-spec/20260825-02-high-grade-peer-review-chat|ช่องแชทรีวิวและแนะนำวิธีการเรียนจากนักศึกษาเกรดสูง]]
**อ้างอิง Acceptance Criteria:** [[./20260912-01-acceptance-criteria-high-grade-peer-review-chat|Acceptance Criteria]]
**วันที่สร้าง:** 2026-09-12

## ขอบเขตการทดสอบ (Scope)

### อยู่ในขอบเขต (In Scope)
- ห้องแชทกลุ่มแยกตามรายวิชา สำหรับนักศึกษาที่ลงทะเบียนวิชานั้นในภาคการศึกษาปัจจุบัน
- กลไกระบบเสนอชื่อนักศึกษาที่เข้าเกณฑ์ผลการเรียนสูงเป็นผู้แนะนำ/ผู้รีวิว (รวมการตั้งค่าเกณฑ์แบบ configurable)
- ขั้นตอนแอดมินยืนยันความเหมาะสม (approve/reject) ก่อนให้สิทธิ์ผู้แนะนำ
- การตรวจสอบเนื้อหาก่อนเผยแพร่ (pre-moderation) สำหรับทุกข้อความในห้องแชท ทั้งจากผู้แนะนำและนักศึกษาทั่วไป

### ไม่อยู่ในขอบเขต (Out of Scope)
- การให้คำแนะนำแบบอัตโนมัติจากระบบโดยไม่มีนักศึกษาจริงเป็นผู้ให้คำแนะนำ (ครอบคลุมในเอกสาร personalized-learning-reminder แยกต่างหาก)
- ห้องแชทหรือฟอรัมที่เปิดกว้างข้ามรายวิชา/ทั้งระบบ
- ระบบให้คะแนน/รีวิวผู้ให้คำแนะนำ และระบบรายงานเนื้อหาไม่เหมาะสมภายหลังโพสต์ (post-moderation)
- การถอนสิทธิ์ผู้แนะนำอัตโนมัติเมื่อผลการเรียนภาคถัดไปตกต่ำกว่าเกณฑ์ (ยังไม่มีกลไกระบุใน spec/prototype)

## Test Strategy

เนื่องจากฟีเจอร์นี้เน้นเรื่อง **การควบคุมสิทธิ์เข้าถึง (access control ตามการลงทะเบียนวิชา/ภาคการศึกษา)** และ **workflow การอนุมัติ 2 ชั้น** (อนุมัติผู้แนะนำ + pre-moderation ข้อความ) จึงแนะนำให้ทดสอบดังนี้:

- **Manual functional testing** เป็นหลักสำหรับ UI flow ทั้ง 3 persona (ผู้แนะนำ, นักศึกษาทั่วไป, แอดมิน) ผ่านหน้าจอ prototype (`chat-room-list`, `subject-chat-room`, `mentor-status`, `mentor-approval-queue`, `mentor-criteria-settings`, `message-moderation-queue`)
- **Automated regression testing** ควรครอบคลุมกฎ business rule ที่เป็น gate สำคัญและมีความเสี่ยงสูงหากพัง ได้แก่ การจำกัดสิทธิ์เข้าถึงห้องแชทตามการลงทะเบียน (BR3) และการบังคับ pre-moderation ทุกข้อความไม่มีข้อยกเว้น (BR4) — ควรเขียนเป็น integration test ระดับ API/service เพื่อป้องกัน regression ในอนาคต
- **Boundary/data-driven testing** สำหรับเกณฑ์เกรด/GPA ที่ configurable (เช่น ค่าเท่ากับเกณฑ์พอดี, ต่ำกว่าเกณฑ์เล็กน้อย, สูงกว่าเกณฑ์มาก)
- **Exploratory testing** สำหรับ edge case ที่ spec ยังไม่ระบุชัด (เช่น วิชาที่ยังไม่มีผู้แนะนำ, การเปลี่ยนเกณฑ์กลางภาค) เพื่อเก็บเป็น feedback สำหรับ spec เวอร์ชันถัดไป

## Test Data

- บัญชีนักศึกษา 4 แบบ: (1) ลงทะเบียนวิชา A ภาคปัจจุบัน + เกรด/GPA ถึงเกณฑ์ที่ตั้งไว้ของวิชา A, (2) ลงทะเบียนวิชา A แต่เกรด/GPA ต่ำกว่าเกณฑ์, (3) ไม่ได้ลงทะเบียนวิชา A ในภาคปัจจุบัน, (4) เคยผ่านเกณฑ์และได้รับอนุมัติเป็นผู้แนะนำแล้วของวิชา A
- บัญชีแอดมิน 1 บัญชี ที่มีสิทธิ์เข้าหน้า `mentor-approval-queue`, `mentor-criteria-settings`, `message-moderation-queue`
- ค่าตั้งเกณฑ์ตัวอย่างต่อวิชา (อ้างอิงตัวอย่างจาก wireframe): วิชา A ใช้ "เกรดรายวิชา = A", วิชา B ใช้ "GPA สะสม = 3.50" _(ตัวเลขจริงต้องยืนยันกับผู้ใช้ในขั้น implementation)_
- วิชา B ที่ยังไม่มีนักศึกษาผ่านการอนุมัติเป็นผู้แนะนำเลย (สำหรับทดสอบ empty state)
- ข้อความทดสอบ: ข้อความคำแนะนำที่เหมาะสม (สำหรับ approve), ข้อความว่าง/ไม่มีเนื้อหา (สำหรับ negative validation), ข้อความที่เข้าเงื่อนไขไม่เหมาะสม (สำหรับ reject ใน pre-moderation)
