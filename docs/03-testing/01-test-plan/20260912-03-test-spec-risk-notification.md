## TS-01: แจ้งเตือนเมื่อ GPA ต่ำกว่าเกณฑ์

**อ้างอิงจาก:** TC-01 / AC-1 (main flow, ตัวแปร GPA)
**Priority:** High
**ประเภท:** Positive

### วัตถุประสงค์
ยืนยันว่าระบบตรวจจับเงื่อนไข "GPA ต่ำกว่าเกณฑ์" และส่งการแจ้งเตือนแบบ in-app ทันทีที่ตรวจพบ

### Precondition
- มีบัญชี Persona #2 (เสี่ยงจากเกรดต่ำกว่าเกณฑ์เพียงตัวแปรเดียว) ที่ GPA ปัจจุบันอยู่ที่ 2.00 พอดี (ยังไม่ต่ำกว่าเกณฑ์)
- ตัวแปรอื่น (การเข้าเรียน, การส่งงาน, แนวโน้มคะแนน) ต้องไม่เข้าเงื่อนไขเสี่ยงใดๆ เพื่อแยกผลได้ชัดว่าการแจ้งเตือนมาจากตัวแปร GPA เท่านั้น

### Test Data / Environment
| รายการ | ค่าก่อนทดสอบ | ค่าหลังทดสอบ |
|---|---|---|
| GPA | 2.00 (boundary, ไม่เข้าเงื่อนไข) | 1.99 (ต่ำกว่าเกณฑ์ 2.00) |
| อัตราเข้าเรียน | 95% (ไม่เข้าเงื่อนไข) | 95% (ไม่เปลี่ยน) |
| จำนวนงานที่ไม่ส่งสะสม | 0 ครั้ง | 0 ครั้ง (ไม่เปลี่ยน) |
| แนวโน้มคะแนน 2 ช่วงเวลาล่าสุด | คงที่ | คงที่ (ไม่เปลี่ยน) |

### ขั้นตอนทดสอบ

| # | การกระทำ | Input | ผลลัพธ์ที่คาดหวัง |
|---|---|---|---|
| 1 | บันทึกผลการเรียนให้ GPA ของ Persona #2 ลดลงเป็น 1.99 | GPA = 1.99 | ระบบบันทึกข้อมูลสำเร็จ ไม่มี error |
| 2 | สั่งให้ระบบประเมินเงื่อนไขความเสี่ยงรอบใหม่ | — | ระบบประมวลผลสำเร็จ |
| 3 | เปิดศูนย์การแจ้งเตือน in-app ของ Persona #2 | บัญชี Persona #2 | มีการแจ้งเตือนใหม่ปรากฏทันที ระบุเงื่อนไข "เกรดต่ำกว่าเกณฑ์" |

### ผลลัพธ์รวมที่คาดหวัง (Expected Result)
ระบบส่งการแจ้งเตือน in-app ทันทีที่ GPA ตกต่ำกว่า 2.00 โดยระบุเงื่อนไขที่ถูกกระตุ้นชัดเจน

### Postcondition
Reset GPA ของ Persona #2 กลับเป็นค่า baseline ก่อนใช้ในเทสเคสอื่น

### Dependency
ไม่พึ่งพาเทสเคสอื่น เป็นเทสพื้นฐานที่ TS-08 (ใน [[./20260908-01-test-spec-personalized-recommendation|Test Spec: คำแนะนำเฉพาะบุคคล]]) ต้องรันตามหลัง

## TS-03: แจ้งเตือนเมื่อไม่ส่งงานสะสมเกินเกณฑ์

ยืนยันว่าระบบตรวจจับเงื่อนไข "ไม่ส่งงานเกินเกณฑ์" และส่งการแจ้งเตือนแบบ in-app ทันที

### Precondition
- มีบัญชีผู้ใช้ที่ยังไม่พลาดส่งงานในรายวิชาเดียวกัน (0 ครั้ง)
- ตัวแปรอื่นต้องไม่เข้าเงื่อนไขเสี่ยงใดๆ

### Test Data / Environment

|---|---|---|
| จำนวนงานที่ไม่ส่งสะสม (รายวิชาเดียวกัน) | 2 ครั้ง (boundary, ไม่เข้าเงื่อนไข) | 3 ครั้ง (เข้าเงื่อนไข ≥ 3) |
| GPA | 3.20 (ไม่เข้าเงื่อนไข) | 3.20 (ไม่เปลี่ยน) |
| อัตราเข้าเรียน | 95% (ไม่เข้าเงื่อนไข) | 95% (ไม่เปลี่ยน) |
| แนวโน้มคะแนน 2 ช่วงเวลาล่าสุด | คงที่ | คงที่ (ไม่เปลี่ยน) |

### ขั้นตอนทดสอบ

| # | การกระทำ | Input | ผลลัพธ์ที่คาดหวัง |
|---|---|---|---|
| 1 | บันทึกการไม่ส่งงาน/ไม่ทำแบบทดสอบครั้งที่ 3 ในรายวิชาเดียวกัน | จำนวนไม่ส่งงานสะสม = 3 ครั้ง | ระบบบันทึกข้อมูลสำเร็จ |
| 2 | สั่งให้ระบบประเมินเงื่อนไขความเสี่ยงรอบใหม่ | — | ระบบประมวลผลสำเร็จ |
| 3 | เปิดศูนย์การแจ้งเตือน in-app ของผู้ใช้ | บัญชีทดสอบ | มีการแจ้งเตือนใหม่ปรากฏทันที ระบุเงื่อนไข "ไม่ส่งงานเกินเกณฑ์" |

### ผลลัพธ์รวมที่คาดหวัง (Expected Result)

### Postcondition
Reset จำนวนงานที่ไม่ส่งสะสมของบัญชีทดสอบกลับเป็น 0

### Dependency
ไม่พึ่งพาเทสเคสอื่น

## TS-04: แจ้งเตือนเมื่อแนวโน้มผลการเรียนลดลงต่อเนื่อง

**อ้างอิงจาก:** TC-04 / AC-1 (main flow, ตัวแปรแนวโน้มคะแนน)
**Priority:** High
**ประเภท:** Positive

### วัตถุประสงค์
ยืนยันว่าระบบตรวจจับเงื่อนไข "แนวโน้มผลการเรียนลดลงต่อเนื่อง" เมื่อคะแนนลดลงติดต่อกันอย่างน้อย 2 ช่วงเวลาประเมิน

### Precondition
- มีบัญชีผู้ใช้ที่มีคะแนนคงที่/เพิ่มขึ้นในช่วงเวลาก่อนหน้า
- ตัวแปรอื่นต้องไม่เข้าเงื่อนไขเสี่ยงใดๆ

### Test Data / Environment
| ช่วงเวลาประเมิน | คะแนนสอบ/คะแนนเก็บ |
|---|---|
| รอบที่ 1 (baseline) | 80 |
| รอบที่ 2 | 75 (ลดลง) |
| รอบที่ 3 | 68 (ลดลงต่อเนื่อง — ครบ 2 ช่วงเวลาติดกัน) |

### ขั้นตอนทดสอบ

| # | การกระทำ | Input | ผลลัพธ์ที่คาดหวัง |
|---|---|---|---|
| 1 | บันทึกคะแนนรอบที่ 1 (baseline = 80) | คะแนน = 80 | บันทึกสำเร็จ |
| 2 | สั่งให้ระบบประเมินเงื่อนไขความเสี่ยง | — | ไม่มีการแจ้งเตือนแนวโน้ม (ยังมีข้อมูลรอบเดียว) |
| 3 | บันทึกคะแนนรอบที่ 2 (ลดลงเป็น 75) แล้วสั่งประเมินอีกครั้ง | คะแนน = 75 | ยังไม่ถือว่าลดลง "ต่อเนื่อง" (มีแค่ 1 รอบที่ลดลง) — ไม่มีการแจ้งเตือนแนวโน้ม _(สมมติฐาน: ต้องลดลงติดกัน ≥ 2 รอบนับจาก baseline)_ |
| 4 | บันทึกคะแนนรอบที่ 3 (ลดลงต่อเนื่องเป็น 68) แล้วสั่งประเมินอีกครั้ง | คะแนน = 68 | มีการแจ้งเตือนใหม่ปรากฏทันที ระบุเงื่อนไข "แนวโน้มผลการเรียนลดลงต่อเนื่อง" |

### ผลลัพธ์รวมที่คาดหวัง (Expected Result)
ระบบส่งการแจ้งเตือนก็ต่อเมื่อคะแนนลดลงติดต่อกันครบ 2 ช่วงเวลาประเมิน ไม่ใช่ทันทีที่ลดลงเพียงรอบเดียว

### Postcondition
Reset ประวัติคะแนนของบัญชีทดสอบกลับเป็น baseline

### Dependency
ไม่พึ่งพาเทสเคสอื่น

## TS-05: ไม่แจ้งเตือนเมื่อไม่เข้าเงื่อนไขเสี่ยงใดๆ

**อ้างอิงจาก:** TC-05 / AC-1 (negative — no risk)
**Priority:** High
**ประเภท:** Negative

### วัตถุประสงค์
ยืนยันว่าระบบไม่ส่งการแจ้งเตือนที่ไม่จำเป็น (false positive) เมื่อผู้ใช้ไม่เข้าเงื่อนไขเสี่ยงข้อใดเลย

### Precondition
- มีบัญชี Persona #1 (Baseline) ที่ไม่เข้าเงื่อนไขเสี่ยงตัวแปรใดเลย

### Test Data / Environment
| รายการ | ค่า |
|---|---|
| GPA | 3.50 |
| อัตราเข้าเรียน | 95% |
| จำนวนงานที่ไม่ส่งสะสม | 0 ครั้ง |
| แนวโน้มคะแนน 2 ช่วงเวลาล่าสุด | คงที่/เพิ่มขึ้น |

### ขั้นตอนทดสอบ

| # | การกระทำ | Input | ผลลัพธ์ที่คาดหวัง |
|---|---|---|---|
| 1 | สั่งให้ระบบประเมินเงื่อนไขความเสี่ยงของ Persona #1 | Persona #1 (Baseline) | ระบบประมวลผลสำเร็จ ไม่มี error |
| 2 | เปิดศูนย์การแจ้งเตือน in-app ของ Persona #1 | บัญชี Persona #1 | ไม่มีการแจ้งเตือนความเสี่ยงใหม่ปรากฏ |

### ผลลัพธ์รวมที่คาดหวัง (Expected Result)
ระบบไม่ส่งการแจ้งเตือนความเสี่ยงเมื่อผู้ใช้ไม่เข้าเงื่อนไขใดๆ

### Postcondition
ไม่ต้อง reset ข้อมูล (ไม่มีการเปลี่ยนแปลงสถานะ)

### Dependency
ไม่พึ่งพาเทสเคสอื่น

## TS-06: แจ้งเตือนแบบรวมเมื่อเข้าเงื่อนไขเสี่ยงหลายตัวแปรพร้อมกัน

**อ้างอิงจาก:** TC-06 / AC-1 (edge case — multi-risk)
**Priority:** Medium
**ประเภท:** Edge

### วัตถุประสงค์
ยืนยันว่าเมื่อผู้ใช้เข้าเงื่อนไขเสี่ยงหลายตัวแปรพร้อมกันในรอบประเมินเดียว ระบบต้องรวมเป็นการแจ้งเตือน 1 รายการที่ระบุครบทุกเงื่อนไข ไม่ส่งซ้ำหลายรายการ ตามที่ระบุใน Edge Cases ของ User Journey ("นักเรียนที่เข้าเงื่อนไขเสี่ยงหลายตัวแปรพร้อมกัน")

### Precondition
- มีบัญชี Persona #4 (multi-risk) ที่ยังไม่เข้าเงื่อนไขเสี่ยงใดๆ ในรอบก่อนหน้า

### Test Data / Environment
| รายการ | ค่า |
|---|---|
| GPA | 1.85 (< 2.00 → เข้าเงื่อนไข) |
| อัตราเข้าเรียน | 70% (< 80% → เข้าเงื่อนไข) |
| จำนวนงานที่ไม่ส่งสะสม | 4 ครั้ง (≥ 3 → เข้าเงื่อนไข) |
| แนวโน้มคะแนน 2 ช่วงเวลาล่าสุด | คงที่ (ไม่เข้าเงื่อนไข) |

### ขั้นตอนทดสอบ

| # | การกระทำ | Input | ผลลัพธ์ที่คาดหวัง |
|---|---|---|---|
| 1 | บันทึกข้อมูลผลการเรียนของ Persona #4 ให้เข้าเงื่อนไขทั้ง 3 ตัวแปรพร้อมกันตามตาราง Test Data | ค่าตามตารางด้านบน | บันทึกสำเร็จ |
| 2 | สั่งให้ระบบประเมินเงื่อนไขความเสี่ยงรอบใหม่ | — | ระบบประมวลผลสำเร็จ |
| 3 | เปิดศูนย์การแจ้งเตือน in-app ของ Persona #4 และนับจำนวนรายการแจ้งเตือนใหม่ | บัญชี Persona #4 | มีการแจ้งเตือนใหม่ปรากฏ **1 รายการเท่านั้น** (ไม่ใช่ 3 รายการแยกกัน) |

## TS-07: รายละเอียดการแจ้งเตือนแสดงเงื่อนไขครบและลิงก์ไปหน้าคำแนะนำ

**อ้างอิงจาก:** TC-07 / AC-1 (edge case — notification detail)
**Priority:** Medium
**ประเภท:** Positive

### วัตถุประสงค์
ยืนยันว่าหน้ารายละเอียดการแจ้งเตือนแสดงเงื่อนไขที่ถูกกระตุ้นครบถ้วน และมีลิงก์นำไปสู่หน้าคำแนะนำเฉพาะบุคคลที่เกี่ยวข้อง ตามที่ระบุใน User Journey ("เปิดดูรายละเอียดการแจ้งเตือน")

### Precondition
- มีการแจ้งเตือนที่ถูกส่งแล้วจาก TS-01 (เงื่อนไข "เกรดต่ำกว่าเกณฑ์")

### Test Data / Environment
| รายการ | ค่า |
|---|---|
| การแจ้งเตือนต้นทาง | ผลจาก TS-01 (เงื่อนไข "เกรดต่ำกว่าเกณฑ์") |

### Dependency
