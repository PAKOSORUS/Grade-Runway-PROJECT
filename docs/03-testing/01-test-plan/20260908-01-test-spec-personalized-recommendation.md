## TS-08: คำแนะนำต้องแตกต่างกันตามตัวแปรเสี่ยงเฉพาะของแต่ละคน

**อ้างอิงจาก:** TC-08 / AC-2 (main flow) / BR3 — "คำแนะนำเฉพาะบุคคล ห้ามเป็นข้อความสำเร็จรูปเดียวกัน"
**Priority:** High
**ประเภท:** Positive

### วัตถุประสงค์
ยืนยันว่าเอนจินคำแนะนำคำนวณเนื้อหาจากตัวแปรเสี่ยงเฉพาะของผู้ใช้แต่ละคนจริง ไม่ใช่การสุ่มเลือกจากชุดข้อความสำเร็จรูปที่ตายตัว

### Precondition
- มีผู้ใช้ 2 บัญชีที่ผ่านการประเมินเงื่อนไขความเสี่ยงแล้ว และมีข้อมูลย้อนหลังครบตามเกณฑ์ขั้นต่ำ (≥ 2 ช่วงเวลาประเมิน)
- ผู้ใช้ทั้งสองต้องเข้าเงื่อนไขเสี่ยงจาก **ตัวแปรคนละตัว** ไม่ปนกัน เพื่อให้แยกผลได้ชัดเจนว่าคำแนะนำอ้างอิงตัวแปรของใคร

### Test Data / Environment
| รายการ | Persona A (Student-A) | Persona B (Student-B) |
|---|---|---|
| GPA | 3.20 (ไม่เข้าเงื่อนไข) | 3.20 (ไม่เข้าเงื่อนไข) |
| อัตราเข้าเรียน | 65% (< 80% เกณฑ์ → เข้าเงื่อนไข) | 95% (ไม่เข้าเงื่อนไข) |
| จำนวนงานที่ไม่ส่งสะสม | 0 ครั้ง (ไม่เข้าเงื่อนไข) | 4 ครั้ง (≥ 3 เกณฑ์ → เข้าเงื่อนไข) |
| แนวโน้มคะแนน 2 ช่วงเวลาล่าสุด | คงที่ (ไม่เข้าเงื่อนไข) | คงที่ (ไม่เข้าเงื่อนไข) |
| จำนวนช่วงเวลาประเมินที่มีข้อมูล | 3 ช่วงเวลา | 3 ช่วงเวลา |

ผลลัพธ์ที่ตั้งใจให้เกิด: Student-A เสี่ยงจาก "อัตราขาดเรียนเกินเกณฑ์" เพียงตัวแปรเดียว, Student-B เสี่ยงจาก "ไม่ส่งงานเกินเกณฑ์" เพียงตัวแปรเดียว

### ขั้นตอนทดสอบ

| # | การกระทำ | Input | ผลลัพธ์ที่คาดหวัง |
|---|---|---|---|
| 1 | บันทึกข้อมูลผลการเรียนของ Student-A และ Student-B ตามตาราง Test Data | ค่าตามตารางด้านบน | ระบบบันทึกข้อมูลสำเร็จ ไม่มี error |
| 2 | สั่งให้ระบบประเมินเงื่อนไขความเสี่ยงรอบใหม่สำหรับผู้ใช้ทั้งสอง | — | Student-A ได้รับแจ้งเตือนเงื่อนไข "อัตราขาดเรียนเกินเกณฑ์"; Student-B ได้รับแจ้งเตือนเงื่อนไข "ไม่ส่งงานเกินเกณฑ์" (ยืนยัน precondition ก่อนเข้าสเต็ปคำแนะนำ) |
| 3 | Login เป็น Student-A แล้วเปิดหน้าคำแนะนำแนวทางการเรียนเฉพาะบุคคล | บัญชี Student-A | หน้าคำแนะนำแสดงเนื้อหาที่อ้างอิงถึง "การเข้าเรียน" โดยตรง (เช่น คำแนะนำเกี่ยวกับการจัดตารางเวลา/ปรับปรุงการเข้าเรียน) |
| 4 | บันทึกเนื้อหาคำแนะนำที่ Student-A เห็นไว้เปรียบเทียบ | — | ได้ข้อความคำแนะนำฉบับเต็มของ Student-A |
| 5 | Login เป็น Student-B แล้วเปิดหน้าคำแนะนำแนวทางการเรียนเฉพาะบุคคล | บัญชี Student-B | หน้าคำแนะนำแสดงเนื้อหาที่อ้างอิงถึง "การส่งงาน" โดยตรง (เช่น คำแนะนำเกี่ยวกับการวางแผนส่งงาน/การจัดการเวลาทำการบ้าน) |
| 6 | เปรียบเทียบเนื้อหาคำแนะนำของ Student-A (สเต็ป 4) กับ Student-B (สเต็ป 5) | ข้อความทั้งสองชุด | เนื้อหาต้องไม่ซ้ำกัน (ไม่ใช่ template เดียวกันที่แทนแค่ชื่อ) และแต่ละฉบับต้องพาดพิงถึงตัวแปรเสี่ยงของเจ้าของบัญชีเท่านั้น ไม่ใช่ตัวแปรของอีกฝ่าย |

### ผลลัพธ์รวมที่คาดหวัง (Expected Result)
คำแนะนำของ Student-A และ Student-B แตกต่างกันอย่างมีนัยสำคัญ และเนื้อหาสอดคล้องกับตัวแปรเสี่ยงเฉพาะของแต่ละคนตามที่ระบุใน BR3

### Postcondition
ล้างข้อมูลทดสอบ (reset ค่าเข้าเรียน/การส่งงานของทั้งสองบัญชี) ก่อนใช้บัญชีนี้ในเทสเคสอื่น เพื่อไม่ให้ตกค้างไปกระทบเทสถัดไป

### Dependency
ต้องรันหลัง TC-01–TC-03 (ยืนยันว่า engine ตรวจจับเงื่อนไขรายตัวแปรทำงานถูกต้องก่อน) เนื่องจาก TS-08 พึ่งพากลไกตรวจจับเงื่อนไขเป็น precondition

## TS-09: Fallback เมื่อข้อมูลย้อนหลังไม่พอสำหรับคำนวณคำแนะนำ

**อ้างอิงจาก:** TC-09 / AC-2 (edge case) — "นักเรียนใหม่ยังไม่มีข้อมูลย้อนหลังพอ"
**Priority:** Medium
**ประเภท:** Edge

### วัตถุประสงค์
ยืนยันว่าระบบไม่แสดงคำแนะนำที่คำนวณจากข้อมูลไม่เพียงพอ (ซึ่งอาจผิดพลาด/ไม่น่าเชื่อถือ) แต่แสดงข้อความ fallback แทนตามที่ระบุใน AC-2

### Precondition
- มีบัญชีผู้ใช้ใหม่ (Student-New) ที่เพิ่งเข้าใช้ระบบ Grade Runway
- ยังไม่มีข้อมูลผลการเรียนครบ 2 ช่วงเวลาประเมิน (เกณฑ์ข้อมูลขั้นต่ำตาม AC-2)

### Test Data / Environment
| กรณีย่อย | จำนวนช่วงเวลาประเมินที่มีข้อมูล |
|---|---|
| 9a — ไม่มีข้อมูลเลย | 0 ช่วงเวลา |
| 9b — มีข้อมูลไม่ครบเกณฑ์ (boundary ด้านล่าง) | 1 ช่วงเวลา |

### ขั้นตอนทดสอบ

| # | การกระทำ | Input | ผลลัพธ์ที่คาดหวัง |
|---|---|---|---|
| 1 | สร้างบัญชี Student-New ที่ไม่มีข้อมูลผลการเรียนใดๆ (กรณี 9a) | บัญชีใหม่ ไม่มีข้อมูล | สร้างบัญชีสำเร็จ |
| 2 | Login เป็น Student-New แล้วเปิดหน้าคำแนะนำแนวทางการเรียนเฉพาะบุคคล | บัญชี Student-New (9a) | ระบบไม่แสดงคำแนะนำที่คำนวณจากข้อมูลว่าง แต่แสดงข้อความ fallback เช่น "ยังไม่มีข้อมูลเพียงพอสำหรับคำแนะนำเฉพาะบุคคล" และไม่เกิด error/หน้าเปล่า |
| 3 | บันทึกข้อมูลผลการเรียนของ Student-New ให้มีข้อมูล 1 ช่วงเวลาประเมิน (กรณี 9b) | ผลการเรียน 1 ช่วงเวลา | บันทึกสำเร็จ |
| 4 | เปิดหน้าคำแนะนำแนวทางการเรียนเฉพาะบุคคลอีกครั้ง | บัญชี Student-New (9b) | ยังคงแสดงข้อความ fallback เดิม เพราะข้อมูล 1 ช่วงเวลา < เกณฑ์ขั้นต่ำ 2 ช่วงเวลา |
| 5 | บันทึกข้อมูลผลการเรียนเพิ่มอีก 1 ช่วงเวลา (รวมเป็น 2 ช่วงเวลา — boundary พอดีเกณฑ์) | ผลการเรียนช่วงเวลาที่ 2 | บันทึกสำเร็จ |
| 6 | เปิดหน้าคำแนะนำแนวทางการเรียนเฉพาะบุคคลอีกครั้ง | บัญชี Student-New (2 ช่วงเวลาพอดี) | ระบบต้องแสดงคำแนะนำที่คำนวณจริงแล้ว (ไม่ใช่ fallback อีกต่อไป) เนื่องจากข้อมูลครบเกณฑ์ขั้นต่ำพอดี — ยืนยัน boundary ด้านบนของเกณฑ์ |

### ผลลัพธ์รวมที่คาดหวัง (Expected Result)
ระบบแสดงข้อความ fallback ตลอดช่วงที่ข้อมูลย้อนหลังน้อยกว่า 2 ช่วงเวลาประเมิน (สเต็ป 2, 4) และเริ่มแสดงคำแนะนำจริงทันทีที่ข้อมูลครบ 2 ช่วงเวลาพอดี (สเต็ป 6)

### หมายเหตุ (สมมติฐาน)
สเต็ป 5–6 (boundary พอดี 2 ช่วงเวลา) เป็นการทดสอบเพิ่มเติมนอกเหนือจาก TC-09 เดิมในตาราง Test Plan เนื่องจากตาราง TC-09 ระบุเฉพาะกรณี "น้อยกว่า 2 ช่วงเวลา" แต่ spec/AC ไม่ได้ยืนยันชัดเจนว่าที่ "เท่ากับ 2 พอดี" ต้องแสดงคำแนะนำจริงแล้วหรือยัง — สเต็ปนี้จึงอนุมานจากถ้อยคำ "น้อยกว่า 2" ใน AC-2 ว่า 2 พอดีคือค่าที่ผ่านเกณฑ์แล้ว ควรยืนยันกับผู้ใช้/นักออกแบบอีกครั้งหากผลทดสอบไม่ตรงกับพฤติกรรมจริงของระบบ

### Postcondition
ลบ/reset บัญชี Student-New หลังทดสอบเสร็จ เพื่อไม่ให้ปนกับ persona อื่นในรอบทดสอบถัดไป

### Dependency
ไม่พึ่งพาเทสเคสอื่นโดยตรง แต่ควรรันแยกจาก TS-08 เพราะใช้บัญชีคนละสถานะข้อมูล (ใหม่ vs. มีข้อมูลครบ) — หากใช้ persona เดียวกันจะทำให้ precondition ของทั้งสองเทสขัดแย้งกัน
